## Synthesis: Cross-Cutting Patterns

### Pattern 1: Tool-use APIs are converging on JSON-schema function calling
Every major framework (crewAI, OpenAI Agents SDK, Claude Agent SDK) has standardised on JSON-Schema-described function signatures. The `learn-agentic-ai` DACA pattern explicitly lists MCP as the glue layer. This means the "how to describe a tool" problem is effectively solved — the remaining frontier is *tool discovery* and *tool composition*.

### Pattern 2: Memory as infrastructure, not application code
mem0, claude-mem, and nanoclaw all treat persistent memory as a separate infrastructure layer injected into the agent loop, not logic the application manages. This mirrors how databases were separated from business logic in the 2000s.

### Pattern 3: Browser-native agents displacing API-first patterns
browser-use (92k stars) and vercel-labs/agent-browser (31k stars, Rust) treat the browser as the primary interface — not REST APIs. This unlocks arbitrary web-app automation without requiring vendor cooperation.

### Pattern 4: "Nano" / ultra-lightweight agent runtimes
HKUDS/nanobot, qwibitai/nanoclaw, and SXongin/praxis all represent a counter-trend to heavy orchestration frameworks: minimal dependency footprints, single-binary or near-single-binary deploys, personal/local-first usage.

## Top 3 Finds

1. **karpathy/autoresearch** (78,885 stars, 2026-03) — autonomous research agents running on a single GPU with nanochat. Karpathy's involvement signals this is a well-considered architecture, not a demo. The single-GPU constraint is the key insight: most agent research workflows do not require cluster-scale.

2. **thedotmack/claude-mem** (71,994 stars, 2025-08) — context capture + compression + injection for Claude Code sessions. The star count far exceeds the Claude SDK itself, confirming memory management is the #1 user pain point in agentic coding workflows.

3. **qwibitai/nanoclaw** (28,573 stars, 2026-01) — containerised nano-agent with messaging integrations and scheduled jobs. The "runs in containers for security" framing is notable: it treats sandboxing as a first-class design goal, not an afterthought.
