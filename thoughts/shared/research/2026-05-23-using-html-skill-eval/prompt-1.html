Three ways to implement debounced search in a React component

PROMPT Show me three ways to implement debounced search in a React component — with tradeoffs for each.

01Inline useEffect + setTimeout

Debounce logic lives directly inside the component that owns the input.

import { useState, useEffect } from 'react';

export function TaskSearch({ onQuery }) {
  const [draft, setDraft] = useState('');

  useEffect(() => {
    const id = setTimeout(() => onQuery(draft), 300);
    return () => clearTimeout(id);
  }, [draft, onQuery]);

  return (
    <input
      value={draft}
      onChange={(e) => setDraft(e.target.value)}
      placeholder="Search tasks"
    />
  );
}
Pro
Con
Zero new abstractions, zero deps
Logic duplicated wherever search lives
Cleanup colocated with the effect
Tests must mount the whole component
Reader needs no library knowledge
Reaching for a leading edge or maxWait means rewriting it
Bundle: +0 kb LOC: ~12 Reuse: low

02Custom useDebounce hook

One small hook returns a delayed value; any component imports and reuses it.

// hooks/useDebounce.ts
import { useState, useEffect } from 'react';

export function useDebounce<T>(value: T, delay = 300): T {
  const [v, setV] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setV(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return v;
}

// TaskSearch.tsx
export function TaskSearch({ onQuery }) {
  const [draft, setDraft] = useState('');
  const debounced = useDebounce(draft, 300);
  useEffect(() => onQuery(debounced), [debounced, onQuery]);
  return <input value={draft} onChange={(e) => setDraft(e.target.value)} />;
}
Pro
Con
One implementation reused across the app
Adds an abstraction every reader must learn
Unit-testable in isolation with act()
Trailing-edge only — no leading edge, no maxWait
Generic over T; works for any input shape
Caller still wires the effect that consumes the value
Bundle: +0 kb LOC: ~10 (hook) + 4 (site) Reuse: high

03lodash.debounce + useMemo

Wrap the production-grade lodash debouncer in a memoized callback; pay bytes, get features.

import { useMemo, useEffect } from 'react';
import debounce from 'lodash.debounce';

export function TaskSearch({ onQuery }) {
  const debouncedQuery = useMemo(
    () => debounce(onQuery, 300, { leading: false, maxWait: 1000 }),
    [onQuery]
  );

  useEffect(() => () => debouncedQuery.cancel(), [debouncedQuery]);

  return (
    <input
      onChange={(e) => debouncedQuery(e.target.value)}
      placeholder="Search tasks"
    />
  );
}
Pro
Con
Battle-tested implementation; edge cases handled
~4 kb gzipped (lodash.debounce standalone)
leading, trailing, maxWait all available
Forget useMemo and you get a fresh debouncer per render
.cancel() and .flush() for unmount and submit
Cleanup is a second effect — easy to omit
Bundle: +4 kb gz LOC: ~14 Reuse: medium

Recommendation

Go with approach 02, the custom useDebounce hook. It removes duplication the moment a second search input appears, stays zero-dep, and the implementation is small enough to read in one sitting — everything most apps need.

Pick 03 (lodash) instead when you actually need maxWait, leading-edge firing, or .flush() on submit — rebuilding those into a custom hook is how a 10-line hook becomes a 60-line one. Pick 01 (inline) only if you have exactly one search input in the whole app and expect that to stay true.
