Research · Herdr plugin API × ralph-herdr · 2026-08-10

Herdr's plugin API, what ralph-herdr actually uses, and where the leverage is

TL;DR — Herdr protocol 19 exposes 90 socket methods, 6 manifest sections, 5 action contexts, live event subscriptions, sidebar metadata tokens, and declarative agent views. ralph-herdr uses two manifest sections, one action context, and zero of the event/metadata/view surface — the cockpit is a polling shell script sitting on an event-driven runtime. The board-as-queue + terminal-cockpit direction is a genuine gap (nobody combines a vendor-neutral GitHub Projects queue with a local multiplexer), and the two highest-leverage moves are an event-subscribed watcher daemon replacing the poll loops, and a one-command board init that collapses today's ten-step manual bootstrap.

1 · The Herdr plugin API, mapped

Herdr's stated design is "the entire Herdr CLI is the plugin API" — a plugin is a directory with herdr-plugin.toml plus commands in any language, escalating through a documented ladder: agent skill → CLI wrappers → raw newline-delimited-JSON socket (~/.config/herdr/herdr.sock, discoverable via herdr api schema).

Socket API highlights a long-running plugin process can use

  • events.subscribe — persistent connection, pushed JSON lines for workspace/tab/pane/worktree lifecycle, pane.agent_status_changed (filterable by status), and pane.output_matched (substring/regex watch on live output). events.wait is the one-shot variant. No event history — live only.
  • pane.report_metadata / workspace.report_metadata — plugins can push up to 16 named tokens (with TTLs) per report that render in sidebar rows, plus set pane title, display-agent, and state labels. This is a sanctioned presentation channel for things like issue=GH-1743, state=In Review, claim=9m.
  • agent.view.set — declarative sidebar projections: filter/sort the agent list by status, seen-ness, or metadata tokens, owned per plugin source. A "ralph lens" over the herd is a config object, not a TUI.
  • layout.export / layout.apply — portable BSP layout trees with labels, cwd, and argv (does not preserve live PTYs). This is Herdr's native "session template" primitive.
  • pane.report_agent / report_agent_session — a session can self-report semantic status and a resume ref, overriding screen-scrape detection.
  • notification.show (240-char body, sound, rate-limited), worktree.create/open/remove, full pane/agent driving (prompt --wait, wait --until, read, send_keys), plugin.pane.open with per-open env map and placement overrides.

Hard limits (explicit in docs)

  • No runtime registration — actions/panes/link handlers are manifest-declared; re-link to change.
  • No custom TUI widgets or keybinding contribution — UI is panes + notifications + sidebar tokens/agent-views only; keybindings live in the user's config.toml.
  • No notification click callbacks — only the user-side open_notification_target keybinding focuses the target.
  • No sandboxing, no permissions model, no plugin auto-update — reinstall to update; --ref pins; marketplace (GitHub topic herdr-plugin, ~530 entries) is unvetted.
  • Popup panes are invisible to pane/agent APIs — no pane ID, no lifecycle events.
  • Panes inherit the server's env, not your shell's — the root cause of ralph-herdr's board-discovery workaround (GH-1761) and why env-var knobs are the wrong config channel.

2 · What ralph-herdr uses today

The shipped plugin (v0.1.0, one commit stale in the installed snapshot) is seven workspace-context actions fronting six pane entrypoints: work-next, work-fleet (cap 4), deliver-pass, tend-pass, doctor (popup), dashboard (split-right poll loop, 120s), and pane-less attend (focus first blocked agent). Spawning is disciplined — worktree per issue, agent named gh-N (name uniqueness doubles as the one-live-pass interlock), IDs always parsed from JSON, billing guard, truthful failure panes held open.

But the attention layer is the weak half. notify-watch.sh is a pane-resident process: single-target it blocks on agent wait; multi-target it polls agent get every 15s (bash 3.2 has no wait -n). Close the watcher pane and notifications stop. The design doc's §3.3 blocked⇄Human-Needed bridge and §3.4 in-session lifecycle reporting were specced and never shipped; [[events]], report_metadata, agent.view, and the socket API are all untouched. The dashboard re-derives state every 120s that the server would push for free.

Other audit findings worth fixing regardless of direction repo map, 2026-08-10
  • Board-CLI discovery and MIN_HERDR are duplicated between lib.sh and herdr-setup.sh with only a comment guarding drift.
  • Plugin version never bumped past 0.1.0 despite behavior changes — and Herdr has no auto-update, so installs go silently stale.
  • worktree remove is never called; worktrees/panes accumulate per issue.
  • attend ordering is arbitrary (.[0]); no blocked-duration ranking.
  • No tests in plugin/ralph-herdr/, unlike sibling plugins.
  • --base origin/main only applies to new branches; resuming an existing feature/GH-N may be behind main.

4 · Gap verdict

The gap is real. No tool found combines a durable, vendor-neutral queue (GitHub Projects V2) with a local terminal cockpit and attention routing. The board-driven competitors owned proprietary queues and two of them died with their vendors in early 2026 — which is itself the argument for a queue you don't own. Three caveats shape the strategy:

  • Anthropic is absorbing the cockpit layer (Agent View, agent teams). The defensible part of ralph is board semantics, lane doctrine, and attention routing — not pane management. Invest there.
  • Herdr-ecosystem risk mirrors vibe-kanban's vendor risk. Keep the board logic multiplexer-agnostic (it already is — herdr is "a transport, not a lane" per the design record). The plugin should stay a thin adapter.
  • GitHub API latency/rate limits mean the cockpit should cache board state locally and reconcile, not poll per refresh.

5 · Employing the plugin API better

P1 — Event-driven attention bridge (replaces the poll loops)

Add a [[events]] subscription on pane.agent_status_changed (or a tiny watcher started by [[startup]] holding one events.subscribe connection). On blocked for a gh-N/lane agent: notification.show with sound, push a blocked metadata token, and — the unshipped §3.3 bridge — optionally comment/flip the issue toward Human Needed so the phone-visible board reflects the terminal. This survives closed watcher panes, kills the 15s poll, removes the bash-3.2 workaround, and makes "notified the moment it blocks" actually true. It also un-blocks retiring notify-watch.sh's multi-target mode entirely.

P2 — Sidebar becomes the dashboard: report_metadata + agent.view

Have spawn scripts tag each pane with tokens (issue, lane, pr) and let /ralph:work|deliver|tend self-report semantic state via pane.report_agent / report_metadata when HERDR_ENV=1 (the unshipped §3.4 — a ~10-line hook or skill preamble). Then ship an agent.view.set "ralph lens": blocked first, sorted by blocked-duration. Much of dashboard.sh's render loop dissolves into server-native sidebar state; the dashboard pane can shrink to queue counts only.

P3 — Cockpit as a layout template (the tmuxinator move)

One verb — action cockpit or board cockpit — that layout.applys a saved tree: dashboard split-right, deliver/tend tabs, doctor popup on demand. Persist board↔pane bindings in STATE_DIR; [[startup]] re-arms the watcher and re-applies metadata tokens after restart (resurrect/continuum semantics). Offer cockpit --freeze via layout.export.

P4 — Close the dead ends: link handlers, answer verb, richer contexts

[[link_handlers]] on github.com/.../issues/N → an action that opens/focuses that issue's session or spawns work N — the terminal becomes clickable into the board. Add pane-context actions (contexts=["pane"]): "read this agent's tail", "answer this blocked agent" (popup prompting for text, then agent prompt), "release claim / requeue". Pair with the design doc's proposed board answer N -m verb so every surface inherits it. Move plugin knobs from server-env vars to a CONFIG_DIR file read by lib.sh — fixing the broken-by-design env delivery.

Deliberately not recommended: building a custom TUI (API forbids it — sidebar tokens and panes are the sanctioned surface), notification click actions (unsupported), or unattended arming before the claim-TTL probe runs (see open questions).

6 · Primitive UX roadmap

Spawning a new board: ship board init

Today there is no creation path — board setup only provisions fields on a project the user already created, linked, and numbered by hand, then configured via one of two competing scope schemas. Ten manual steps, and a typo'd project number decorates a stranger's board with only a warning. The fix is one idempotent verb:

board init [--repo owner/name] [--title "..."]
  # 1. gh project create (owner inferred from repo)     — was: GitHub UI
  # 2. link project ↔ repo (linkProjectV2ToRepository)   — was: GitHub UI
  # 3. write .ralph.json scope                           — was: hand-edit, 2 schemas
  # 4. run existing `board setup` (fields, idempotent)
  # 5. run `board doctor` + print readiness next steps
  • Resurrect the v1 golden-template research (copyProjectV2 copies a template project with views/fields intact) as board init --from-template — views are otherwise un-API-able.
  • Make wrong-project detection blocking in init (it creates, so it knows the right number), and collapse to one scope schema with a deprecation shim.
  • Add board init --herdr to chain herdr-setup.sh fix, so repo-zero-to-cockpit is two commands.
  • Longer term: board scaffold for readiness rungs (copy state-guard.yml, merge-pr.sh, PR ruleset via API) — readiness currently recommends seven manual steps and scaffolds none.

Ship Herdr guidance inside the ralph plugin

Today an agent asked to "spawn a work session in herdr" has nothing local to read: the cheatsheet lives in the herdr plugin dir (unreachable from ${CLAUDE_PLUGIN_ROOT}), skills other than /ralph:help herdr never mention Herdr, and hooks are herdr-blind. Concretely:

  • Reference doc in skills — ralph/skills/<lane>/references/herdr-api.md: the sanctioned verbs (spawn_work_session contract, agent naming, --no-focus discipline, ID-from-JSON rule), the ralph-herdr action/entrypoint catalog, and pointers to herdr --skill and herdr api schema for self-discovery. Duplicate or symlink the cheatsheet so it's plugin-root-reachable.
  • Guiding hook — a SessionStart (or skill-preamble) check: if HERDR_ENV=1, inject one line telling the session it's cockpit-hosted, to self-report via pane report-agent, and where the herdr reference lives. This is also the delivery vehicle for §3.4.
  • Escalation-writing guidance — the design doc's unwritten note: blocked questions should be phone-answerable ("pick A or B, default A") since notifications carry 240 chars. Belongs in the work/board skills.
  • Single source of truth — deduplicate board-discovery and MIN_HERDR between lib.sh and herdr-setup.sh; bump the plugin version on every behavior change and have herdr-setup.sh check compare installed vs repo version (Herdr won't auto-update it for you).

7 · Teaching ralph-herdr agents to think in fleets

Four sources examined. The requested ray-amjad/peer-sessions — a Claude Code skill (not a herdr plugin) that runs a fleet of sibling claude sessions on one machine, coordinated via Claude Code 2.1.224's cross-session SendMessage, spawning into cmux or herdr (auto-detected backend: pane split / workspace create + agent start with a settling-retry, readiness verified via herdr agent get). Plus the three closest herdr-marketplace plugins: herdr-peer-review (bash peer-agent sessions), herdr-cadence (Rust; one Lead agent commanding a role fleet), and pi-herd (TS; durable run state + verdict protocol). Together they demonstrate the pattern ralph-herdr lacks: the agent itself is the orchestrator, given a small library of verified spawn/message verbs and a report-back contract.

What peer-sessions gets right (its doctrine, largely portable verbatim)

  • Reply-is-the-notification. A peer's message arrives as a new user turn in the orchestrator — so the loop is spawn → brief → end your turn; no poll loops burning tokens. Briefs end with the sender's literal reply address (peers can't discover who briefed them) and demand a fixed reply format so a large fleet collates for free. ralph-herdr's equivalent: prefer SendMessage peer replies where available; fall back to herdr agent prompt/wait/read — peer-sessions documents exactly when SendMessage is harness-scoped and the herdr surface is the right transport.
  • Placement as a decision table, not a flag dump: split for ≤3 peers of short watched work, workspace (default) for 3+/minutes-long, window for big fleets — ask the user only when the choice changes their screen. Ready-made UX doctrine for a ralph fleet skill.
  • Teardown is opt-in and printed at spawn time. The spawn script emits exact, placement-matched teardown commands using durable UUIDs (refs are indexes that renumber); kill processes first, close UI second (closing UI leaves addressable orphans); close only what you made. Live peers keep context — a follow-up costs one message, not a re-spawn.
  • Honest semantics: success: true means delivered, not done; a send is one-way; the first bare-name send bouncing with a ref is a confirmation, not a failure; --permission-mode auto is the only unattended-viable mode. And the non-optional rule: a peer carries none of the user's authority — never route around a permission denial through another session.
  • Diagnosable failure: peer-addr.py gives a per-session reason for unreachability; peer-inbox.py recovers truncated replies from transcripts; a Codex bridge uses a real Claude relay rather than faking the socket protocol.

The composite pattern worth adopting

  • Ship a fleet skill in the ralph plugin that composes peer-sessions' loop with ralph's board contract. A lane session (or the user) says "fan out": the skill spawns gh-N peers via the existing spawn_work_session path, briefs each with issue scope + reply address + fixed report format, ends its turn, and collates replies as they arrive. Where SendMessage is unavailable/scoped, the same skill drives herdr agent prompt/wait/read. Don't fork peer-sessions — depend on its doctrine and add the board layer (claims, Workflow State, worktree-per-issue) it deliberately doesn't have.
  • Ship a fleet.sh library + skill, peer-review style. A sourced bash library of hardened primitives — peer_launch / peer_ask / peer_decide / peer_exec / peer_escalate / peer_close — plus a SKILL.md that teaches a Claude session to compose them. This is the direct answer to "teach agents to spawn sub-fleets of scripts and agents via the herdr CLI," and it reuses lib.sh's existing discipline (IDs from JSON, --no-focus, billing guard).
  • Cadence's Lead contract: every spawned agent is handed its scope and the exact command line to report completion (agent complete <id> --report-file, JSON: status/summary/tests/changed_paths/commit_sha); the Lead gets exact spawn/list/report/cancel commands in its prompt. File-based JSON reports, never chat-scrollback parsing. The orchestrator pushes updates back into the Lead via herdr agent prompt.
  • Durable run state, pi-herd style: .ralph-herdr/runs/<id>/state.json + artifacts + inbox in-repo, verdict-marker lines (verdict: done|blocked pass=N) in required artifacts as a restart-surviving completion protocol; duplicate-run refusal per lead pane; [[startup]] reconciliation (cadence) so the fleet survives herdr restarts — dovetails with P3's state file.

Hardening tricks to copy verbatim

  • Shell-readiness dance before pane run (peer-review _run_clean): pane split returns before the shell is usable; poll pane process-info until argv0 is a shell, then ctrl+c+ctrl+u — observed live: oh-my-zsh startup eating first characters (codex → odex).
  • Random per-call markers + pane read --source recent-unwrapped to slice an answer out of scrollback without matching the echoed prompt; prompt-via-stdin-file to dodge command-line truncation; process-exit detection (not text sentinels) for headless exec runs.
  • Fatal timeouts — never read stale output after a wait fails; agent_pane_busy retry loops on agent start (ralph-herdr already has this).
  • Dual-channel escalation — local toasts can be config-disabled ([ui.toast]), so pair notification show --sound request with pane report-agent --state blocked --custom-status (phone-visible via herdr-remote), and warn loudly when the remote page fails.
★
Don't rebuild what the marketplace already has: fleet dashboards (herdr-agent-office, herdr-agent-inbox), Telegram gating (herdr-telegram-gate), issue-launchers (herdr-plugin-github-start), PR trackers (herdr-pr-tracker). ralph-herdr's edge stays the board contract; fleet primitives should layer on herdr agent start (cadence's choice) rather than raw send-keys (pi-herd's, partly a herdr-0.7.1 workaround since actions couldn't take arguments).
