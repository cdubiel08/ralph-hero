The parallelism layer is ahead of its identity and isolation model

Verdict: do not ship the sibling-fleet or unattended live-test surfaces unchanged. The branch is impressively tested and generally fail-conscious, but six cross-layer faults survive the suite: independent agents share a mutable checkout; board claim identities do not match Herdr identities; global agent discovery is joined to repo-local work by issue number alone; the ledger mutex can admit simultaneous owners; the live harness deletes sessions it did not create; and untrusted terminal controls render verbatim. These are interaction defects, not ordinary unit-level mistakes—which is why 353 board tests, 561 new shell assertions, BDD, and the Go race suite can all pass beside them.

Architecture and fault lines

The intended control split is sound: GitHub Projects/board state is authoritative; Herdr is execution and presentation; the append-only ledger is recovery memory; contracts are the typed wire. The defects cluster where an identity crosses those layers.

Unifying fix direction: define one immutable runtime identity—{repoScope, issue, agentName, agentRef, paneId, claimHolder, worktree}—at spawn time, persist it before the agent can emit events, and require every board, cockpit, ledger, and routing operation to consume that same object.

Release blockers

F01 · concurrency / data integrity

Sibling fleets run independent workers in one worktree, branch, HEAD, and Git index

critical0.99
fleet.sh:396–417, 493–539 · fleet.test.sh:607–613 · ralph/skills/work/SKILL.md:67–73

Each sibling receives the identical /ralph:work N prompt and --cwd "$wt". There is no role partition, file ownership, coordinator, or integration protocol. That directly contradicts the work contract’s “one worktree per unit … never a shared HEAD.”

A edits X ──┐ A: git add/commit ─┐ ├─ same filesystem → last writer / mixed file ├─ same index → index.lock / mixed commit B edits X ──┘ B: rebase/commit ────┘ moves shared HEAD underneath A

Expected failures include overwritten patches, nondeterministic test results, index.lock contention, commits containing another agent’s half-finished changes, and duplicate PR/board close-out.

Smallest robust fix: disable K > 1 for shared-issue fleets now. Re-enable only with one worktree/branch per worker plus a coordinator that assigns disjoint tasks and integrates reports/commits. A shared checkout needs a real transactional collaboration model; prompts are not one.
F02 · identity / claims / deadlock

Herdr agent identity and board claim identity disagree, producing ghost co-claims

high0.99
board.ts:754–772, 1535–1666, 1888–1932 · contracts.ts:225–231, 927–951 · fleet.sh:400–417, 542–568 · watch-event.sh:376–420

Normal board commands claim as user@hostname. Fleet setup then joins siblings 2…K under names such as w123-fix--2, but no spawned pane receives RALPH_CLAIM_HOLDER=<agent-name>; sibling 1 is not joined at all. L5 nevertheless authenticates completion by Herdr agent name.

On the first move out of In Progress, board removes only the caller (user@host) and deliberately writes remaining named holders back while setting Human Needed/In Review/Done. Those names have no process identity that naturally calls claim leave. answer() then posts the durable answer but cannot reclaim against the fresh “foreign” co-holder.

state = Human Needed claim = w123-fix--2|fresh-time board answer 123 → comment succeeds → Human Needed→In Progress refuses → wait TTL / manual cleanup

The one shared timestamp compounds this: any surviving member heartbeat refreshes every dead holder, so exited names can remain “fresh,” fill the eight-holder cap, and block recovery indefinitely.

Fix the model, not the symptom: give every session a canonical claim identity and join sibling 1; keep claims legal only while state is In Progress; clear the whole claim on a state transition or refuse finalization until an explicit fleet-finalize; use per-holder timestamps or reliable leave-on-exit. Align L5 with that exact identity.
F03 · scope / confidentiality / wrong-target mutation

Global Herdr agents are routed as repo-local work by issue number alone

high0.99
cockpit/fetch.go:203–227, 380–395 · cockpit/model.go:153–199 · lib.sh:364–374 · watch-event.sh:70–84, 178–190 · link-open.sh:84–111 · ralph-answer.sh:127–142

herdr agent list spans all workspaces in a session. The cockpit, spawn suppression, refill capacity, link focus, answer nudge, and ledger routing parse only w<issue>-*/gh-<issue>. In a supported multi-workspace topology, repo A #123 and repo B #123 collide.

  • Repo B can skip spawning because repo A has a live w123-*.
  • Repo B’s cockpit can peek, focus, or prompt repo A’s agent, exposing pane-tail data and sending the wrong instructions.
  • Repo A agents count against repo B’s refill capacity; the first matching ledger can receive the event.

A related documented knob is also incomplete: RALPH_HERDR_REPO changes cfg.Repo/REPO, but Go subprocesses never set cmd.Dir and shell board/gh reads do not cd "$REPO". The UI can label repo A while board commands resolve from caller cwd repo B.

Smallest robust fix: attach a canonical owner/repo scope token to every agent and filter every list/join/route by it. Until then, resolve pane cwd → git remote and cache it. Run all board/gh subprocesses with the configured repo cwd. Add two-repo/same-issue and caller-cwd≠configured-repo integration tests.
F04 · mutex ownership / lost updates

The 15-second stale-lock breaker admits multiple simultaneous owners

highreproduced
ledger.sh:157–211, 349–393 · reconcile.sh:75–115 · watch-event.sh:397–415

The lock is an ownerless directory. Every waiter deletes it after ~15 seconds, regardless of holder PID, start time, or token; unlock is a plain rmdir. Legitimate critical sections call Herdr, token, notification, and repeated full-ledger reductions and can exceed that threshold.

isolated reproduction: holder-A acquired t=1786478769 holder-A still inside t=1786478786 holder-B acquired t=1786478786 ← overlap confirmed

After B recreates the directory, A’s eventual unlock can remove B’s lock, allowing C in too. Consequences include duplicate exit/adoption/notification events, double refill decisions, and stale full-file fleet.json replacements.

Smallest robust fix: use flock/lockf or a small portable helper. If directory locks remain, persist an owner PID + random token, verify liveness before takeover, and unlock only a matching token. Compute snapshots and perform network/notification work outside short critical sections.
F05 · destructive test lifecycle

The live BDD suite adopts and deletes sessions it did not create

high0.99
features/steps/live.steps.ts:54–81, 178–187 · scripts/nightly-live.sh:43–59 · package.json:16

The fixed ralph-bdd name is reused when already running, with no ownership marker. Both the Cucumber After hook and nightly EXIT trap then unconditionally stop and delete it. The nightly trap is installed before the npm opt-in gate, so invoking the script without RALPH_BDD_LIVE=1 still deletes that named session. Overlapping runs can delete each other.

Smallest robust fix: gate before installing cleanup; mint a per-run session name and ownership nonce; refuse/adopt nothing pre-existing; teardown only owned state; verify absence and fail while retaining logs if cleanup fails. If the fixed name is mandatory, add an interprocess lease.
F06 · terminal trust boundary

Issue, comment, error, and pane text reach the terminal with OSC/CSI intact

highreproduced
cockpit/view.go:220–271, 330–341 · cockpit-fzf.sh:35–48, 102–130

GitHub titles/comments and pane tails are rendered verbatim. ANSI-aware truncation preserves control sequences; when text fits, it returns the original bytes. An OSC-52 payload survived the fzf decoration path byte-for-byte. A collaborator-controlled title/comment can manipulate clipboard, title, hyperlinks, colors, cursor position, or visual layout.

Smallest robust fix: sanitize all external strings before applying application styles. Strip OSC/DCS/CSI, C0/C1 controls, CR and embedded line controls; consider bidi controls; preserve printable Unicode and deliberate newlines only. Test OSC-52, CSI, CR, tab, bidi, and long escape boundaries in both renderers.

Concurrency and lifecycle findings

F07 · event ordering

An agent can emit status or exit before its spawn record exists

high0.95
lib.sh:454–480 · fleet.sh:506–520 · watch-event.sh:292–345, 401–409

agent start returns before the spawner mints/appends its ref. A fast hook can discover the same agent and mint ref A; the spawner then appends ref B. If the pane exits in the gap, the hook sees nothing and the later append creates a falsely open record. This breaks the durable epoch premise.

Fix: mint identity and append a provisional pane-bound spawn intent before start; terminalize it on start failure/collision. Make watcher discovery reuse that identity. A long lock around agent start is not safe with the current breaker.
F08 · ABA / durable identity

Bare-name matching conflates recycled agents across epochs

high0.99
watch-event.sh:73–83 · reconcile.sh:80–100, 239–247 · ledger.sh:307–329 · attend.sh:59–65

Several reducers strip #epoch and treat equal names as equal parents/agents. A missed exit followed by reuse of deterministic w123-slug can attach new status to the first old ref, spare a dead epoch because the new name is live, and adopt/orphan children against the wrong generation.

Fix: compare exact refs whenever stored data has an epoch; use pane identity and newest spawn to resolve duplicates; close older open refs as replaced. Retain bare-name fallback only for explicitly legacy records.
F09 · reconcile fail-open

Successful-but-malformed agent JSON marks the entire herd lost

high0.99
reconcile.sh:46–60, 91–105 · watcher.test.sh:367–377

The pass aborts on nonzero command exit, but rc=0 with truncated JSON, {}, missing .result.agents, or a soft error becomes an empty set. The fresh re-probe repeats the same mistake, then appends exit-lost for every open ref. Current tests cover nonzero exit only.

Fix: require jq -e '.result.agents | type == "array"' on both reads; treat wrong shape as unavailable and abort/retry without mutation. Apply the same envelope validator to cockpit and frontier reads.
F10 · refill arming race

Initial workers start before refill state exists, so early completion is lost

medium0.99
work-fleet.sh:73–124 · fleet.sh:119–163

The run spawns all initial workers sequentially and only then writes/arms fleet.json. A worker that finishes during that interval emits a refill trigger that finds no run. All-failed initial launches can produce an armed empty fleet with no later event. Failed initial attempts are also omitted from spawned, contradicting the stated “every attempt spends budget” rule.

Fix: create/arm state first, reserve each initial attempt through the same locked consume/inflight path as refill, and run one immediate capacity reconciliation after initial starts.
F11 · capacity accounting

A done worker still consumes capacity while its pane remains listed

medium0.90
watch-event.sh:178–190, 376–383 · fleet.test.sh:470–480

done triggers refill, but capacity counts every matching agent name regardless of status—including the just-completed one. If the pane stays alive, the hook returns “at capacity” and the fleet remains productively underfilled until another event.

Fix: count only capacity-consuming statuses or explicitly exclude the completed event agent; test done-but-still-listed behavior.
F12 · lost update

Full-file disarm writes bypass the fleet mutex

medium0.90
fleet.sh:198–215 · watch-event.sh:161–164, 259–263

ralph_fleet_disarm reads and replaces the whole JSON file without the scope lock at two call sites. Atomic rename prevents torn JSON, not stale-snapshot overwrite: it can restore armed, lose budget/spawned/inflight changes, or erase a newer disarm reason.

Fix: make every mutator acquire the same owner-safe scope lock internally, or require/assert an already-held token. Add disarm-vs-consume and disarm-vs-spawn_done race tests.
F13 · duplicate spawn

Duplicate prevention fails open and the TUI permits repeated in-flight spawns

medium0.98
lib.sh:364–374, 442–460 · cockpit/update.go:398–409 · cockpit/fetch.go:495–510

A list/parse failure is swallowed as “no live owner,” so an alternate-slug or legacy worker for the issue is missed. In the TUI, pressing s repeatedly launches concurrent five-minute spawn commands with no per-issue in-flight set. Both can fetch/open worktrees before the exact-name loser returns rc=2, leaving an extra pane.

Fix: fail closed on an unknown agent snapshot, add a repo+issue spawn lease in the shared shell path, and maintain a per-issue in-flight set in the model.
F14 · claim write verification

Concurrent claim writes can silently drop co-holders and still “verify”

medium0.92
board.ts:1649–1666, 1753–1775, 1817–1839 · board.fleet.test.ts:204–218, 266–274

GitHub has no CAS. Join/leave verification checks only whether the target holder is present/absent. A last-writer overwrite that preserves the target but drops another holder passes, so parallel claims are not compositionally safe.

Fix: verify the full expected ordered holder set and timestamp/raw value; on mismatch, surface a lost-update refusal and retry from a fresh read. Longer term move claim membership to a store with revision/CAS semantics.
F15 · append-log durability

One truncated ledger line poisons every future whole-file reduction

medium0.90
ledger.sh:219–239, 257–329

Reducers use jq -s over the entire JSONL file. A crash/ENOSPC/unusual filesystem that leaves one partial line makes all later reductions fail; valid later appends do not heal it, and several callers collapse failure into an empty set.

Fix: validate line-by-line, distinguish corruption from empty, quarantine/repair only a malformed tail at startup, and keep a compact materialized state snapshot beside the audit log.
F16 · epoch entropy

Durable refs use only 16 deterministic bits

low0.95
naming.sh:188–199

The epoch is four hex digits derived from second+PID. For repeated respawns of the same deterministic name, collision probability reaches roughly 50% near 301 epochs; a collision reopens old lineage/parent state. Calls in the same process and second produce the same suffix.

Fix: use at least 64 random bits—prefer UUID/128-bit—and keep format validation at boundaries.

F22 · typed identity edge cases

Claim join accepts a holder for another issue; ClaimV2 is not fully V1-compatible
