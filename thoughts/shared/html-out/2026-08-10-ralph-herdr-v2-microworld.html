D1 · Naming grammar

Retiring gh-N. Constraint: Herdr names match [a-z][a-z0-9_-]{0,31}, unique among live agents only (dead names recycle — the ABA hazard is real, so durable refs use name#spawn-epoch). Shared principle across all three: name = identity + scan key; metadata tokens = attributes. The name is immutable at spawn — anything that changes (state, parent-after-adoption, PR#) must live in tokens.

Grammar A · readable

<role>-<issue>-<slug>

work-1743-oauth-refresh · orch-1700-auth-epic
collision → --2 suffix (double-hyphen is reserved)

Most readable; conventional-commit feel; role words self-document Positional parse-back always exact (role, issue = segments 1, 2) Longest overhead — 4-digit issue + "work" leaves ~19-char slug budget Role vocabulary must be a closed registry or parse-back dies
Grammar B · compressed ★ recommended

<lane><issue>-<slug>

w1743-oauth-refresh · o1700-auth-epic · d1743-flaky-probe
lanes: w work · r review · o orch · d disposable · s watcher · x relay

Best sidebar density; all w17xx-* column-align and sort together 6-char overhead → 26-char slug; trivial regex parse ^([a-z])([0-9]+)- Cryptic for newcomers; lane alphabet finite (~6-8 letters) New role class later = migration
Grammar C · lineage-in-name (the foil)

<parent>--<child>

o1700--w1743-oauth — dots are illegal, so -- as path separator

Names are immutable → adoption makes the name lie Depth ≥3 cannot fit in 32 chars, period Parent segment burns 6–12 chars of slug budget Its one good idea — parent visible at a glance — is better served by a sidebar view grouped on the root token

Token complement (any grammar): role · issue · slug(full) · parent · root · depth · state · branch · claim(TTL=claim TTL — expiry becomes visible) · pr · spawn_epoch — 11 of Herdr's 16-token budget, 5 spare.

D2 · Role taxonomy

Key insight: cadence's planner/researcher/developer/qa are job content; your disposable/sibling/orchestrator are lifecycle contracts. The taxonomy should be the lifecycle contract — job content goes in the slug and the brief. A "reviewer" is a disposable whose brief is a PR; it earns a taxonomy slot only if it differs in who reaps it, whether it claims, or whether it fans out.

Minimal-3

disposable · sibling · orchestrator

Every lifecycle question has exactly one answer; fits in your head Infra agents (relay, watcher/janitor) get shoehorned as "orchestrator with no children"

D3 · Agent graph & lineage store — the unlock

Two nesting planes in one graph: herdr peers (visible panes, governed: depth limits, claims, adoption) and in-process Agent-tool subagents (invisible to Herdr, free: auto-die with parent, orphaning impossible by construction — represented as leaf clusters via an inner=N count token). Depth limit: hard max 3 in the herdr plane, enforced at spawn.

A · Append-only JSONL ledger

Durable history

~/.ralph/<repo>/ledger.jsonl — spawn/state/adopt/exit events; graph = fold. IDs are name#epoch.

Full forensics — dead ancestors queryable; survives everything Worktree-per-issue means multi-writer merge hell unless single-writer outside worktrees Drifts from reality on crash — needs reconciliation anyway
B · Herdr tokens only

Live truth

Each agent carries parent= root= depth= state=; graph = agent list + token join. root flattens the transitive closure — "everything under X" is a one-token view filter.

Cannot drift — it is reality; sidebar renders subtrees natively; TTL tokens give free staleness detection Dead agents vanish instantly — no forensics; dies with the herdr daemon
C · Hybrid ★ recommended

Ledger + tokens + watcher reconciles

Agents self-report tokens only; the watcher (D2 ext-5) subscribes to events.subscribe and is the sole ledger appender — single-writer solved. Startup reconciliation: live-but-unledgered → discover; ledgered-but-gone → exit:lost; dead parent → adoption policy.

Durability + live display + drift repair in one design One more moving part; ledger freshness = watcher liveness (mitigate: watcher heartbeat token with TTL → cockpit shows "graph stale")

D4 · Fleets over issue groups

A · Board-frontier pool

Query Ready, keep k live, refill

Claims are the mutex — conflicts are benign skip-and-next; no idle barriers Unmodeled dependency → picks blocked-in-reality work; shared-file rebase churn
B · Epic-subtree orchestrator

Orch claims parent, walks sub-issues

Claim tree mirrors agent tree; merge order is orch-controlled — rebase storms scheduled, not emergent Orch death orphans the subtree (D3 adoption is load-bearing); serialization point past ~8 leaves
C · DAG waves

Topo-sort, barrier per wave

Within-wave conflicts impossible by construction; cleanest history One straggler blocks the barrier; fictional waves when dependency edges are stale
E · Synthesis ★ recommended

Dependency-aware work-stealing frontier

C-as-scheduler + A-as-executor: refill the pool with any issue whose blockers are all merged (streamed Kahn's algorithm). No barriers, no unmodeled pickups.

Degrades only when the dependency graph is wrong — a board-hygiene problem (tend's job), not a fleet problem Requires dependency edges as structured board data, or every viz and wave lies (D5 contract note)

D · Static assignment (human picks the set) stays available as the demo/curated mode — it's a flag, not a strategy decision.

Issue DAG with wave overlay — node fill = board column, ring = agent state; the synthesis streams the frontier instead of waiting at wave boundaries

D5 · Contract stack

Ten boundaries need versioned JSON contracts (C1 SpawnRequest · C2 CompletionReport · C3 FleetBrief · C4 FleetReply · C5 BoardMutation · C6 BoardQueue · C7 LineageRecord · C8 TokenVocabulary · C9 EscalationPayload · C10 the pinned Herdr envelope). C6 is today's most-consumed, least-declared. Every contract: contract + contract_version fields, unknown-higher versions refuse loudly, additionalProperties: false on producers / ignore-unknown on consumers.

A · JSON Schema files in-repo

Language-neutral, herdr-native format

ralph/contracts/*.schema.json; CI = check-jsonschema + ajv over examples/bad-examples; runtime = board contract validate verb + jq structural asserts on hot bash paths.

Off-the-shelf tooling; no toolchain coupling Schema ↔ board.ts type drift needs its own test; cross-field rules are ugly if/then chains
B · Zod-in-board.ts, emitted artifacts ★ recommended

One source where the logic lives

Zod schemas are the TS types (z.infer kills QueueItem drift); zod-to-json-schema emits artifacts for the bash side; CI fails on stale generated files; bash validates via board contract validate or ajv on artifacts.

Parse = validate at every board.ts boundary; superRefine expresses cross-field rules cleanly Generated JSON Schema loses refinements — bash side is structural-only; ties contracts to the TS toolchain
C · CUE structure + policy

One artifact for schema and policy

Constraints like fleet-cap ≤ 4 and TTL bounds are first-class; vets config files too.

Best expressiveness; config vetting for free New toolchain in a "gh + jq" repo; CUE→TS codegen immature; runtime still ends up JSON-Schema-shaped

D6 · Test strategy + BDD executor

Shared pyramid regardless of choice: L0 metaschema/drift checks → L1 round-trips + bad-examples → L2 golden files (recorded herdr responses; every jq expression in lib.sh tested as a unit) → L3 bats with a fake herdr shim (bash 3.2-compatible) → L4 live integration against herdr --session ralph-test (isolated socket) → L5 chaos (server restart mid-wait, pane closed between worktree-create and agent-start, the rc-file race, claim expiry mid-run).

Record/replay-first

Transcript capture + deterministic replays

A herdr wrapper tees every request/response to tests/transcripts/*.jsonl; replays drive the fake shim; protocol upgrades = re-record once, diff.

Fast (<10s), deterministic, no live server in CI; transcript diff doubles as protocol-migration detector Blind to timing races — exactly the bug class this codebase has actually hit; staleness is the failure mode
Live-session-first

Named test session per PR

Highest confidence where it matters (timing, restart semantics); catches herdr upgrades immediately herdr in CI, scratch board + PAT, minutes not seconds, flake management
Hybrid ★ recommended

Replay per-PR + nightly live + incident rule

Rule: every live incident that produces a lib.sh comment must also produce a transcript or chaos case.

Cheap loop + real coverage; institutionalizes the lessons currently memorialized as prose comments Two harnesses to maintain

D8 · Extensibility guardrails

Adapter-strict ★ recommended

Four-verb adapter interface

Cards and skills call focus / prompt / tail / spawn through a ralph cockpit adapter — herdr is implementation #1; tmux/zellij/standalone implement the same four verbs; no adapter degrades every verb to its board/gh equivalent. Answer path is comment-first by construction, so the durable half survives a vanished multiplexer.

Multiplexer-agnostic from day one — the vendor-risk hedge the gap analysis demanded Indirection tax on every call; adapter interface becomes its own contract to version
Herdr-native-first

Direct herdr CLI, abstract later

Less machinery now; herdr verbs are already good Every script grows herdr assumptions; the retreat gets more expensive monthly

Fixed regardless of choice (from all three lenses): append-only events ledger {ts, kind, issue, agent?, from?, to?} feeds all visualizations — reports never read the socket directly; card metadata additive-only with schema_version; sidebar tokens/notifications stay best-effort decoration; dependency edges must be structured board data.

Hero journeys — scope each (v1 / v2 / cut)

J1 · Solo maintainer, morning

Inbox-zero in 12 minutes

  1. Open herdr — cockpit restored, transcripts intact
  2. Attention inbox: 2 blocked, 1 Human Needed, 3 In Review
  3. First card shows the question verbatim → r reply, delivered ✓
  4. Second is a permission prompt → Enter, approve in-pane, hop back
  5. Human Needed (no session) → a answer as issue comment
  6. Skim 3 review diffs via d popups
  7. Spawn deliver-pass; notification: 3 merged
  8. s on top Ready card before context-switching away
touches: naming (scan), tokens, answer contract
J2 · Fleet commander, epic of 12

One intervention, twelve issues

  1. Hand epic #1700 to an orchestrator
  2. DAG view: 12 nodes, 3 waves; wave 1 running
  3. Sidebar groups children under the epic (root token)
  4. Wave 2: two siblings hit the same rebase conflict, block adjacent — pattern visible because cards sit together
  5. Resolve one in-pane; r the other with the fix
  6. Waves complete; deliver merges in dependency order
  7. Lineage tree archived as HTML into the epic's closing comment
touches: lineage, DAG edges as board data, fleet strategy
J3 · Phone-only escalation

The board is the only remote surface

  1. Agent hits an irreversible choice → Human Needed + issue comment with enumerated options ("Recommend B")
  2. GitHub mobile push — no herdr dependency off-desk
  3. Reply "B" from phone
  4. Watcher detects the comment → back to In Progress → agent prompted to re-read and resume
  5. Desk 2h later: inbox empty, PR in review
touches: escalation contract (phone-answerable, enumerated), comment-first answer path
J4 · New adopter

0 → merged PR in 30 minutes

  1. Plugin install; doctor popup: red, but every red line carries its remedy
  2. board init → green
  3. File first issue via intake; work-next spawns w1-…
  4. Ctrl-clicks the issue URL the agent printed — learns the click affordance by accident
  5. Blocked → notification names agent + state → attend → approve
  6. Deliver pass → merged. Five names touched, each did what it said
touches: board init, naming discoverability, doctor remedies
