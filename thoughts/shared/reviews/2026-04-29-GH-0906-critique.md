# Plan Critique: GH-906 — Parser memory_tier Write Path

## Summary

VERDICT: **APPROVED**

A single-phase, single-issue plan that fixes the schema v3 write-path bug (parser drops `memory_tier` frontmatter, all docs land as `'doc'`). The plan accurately describes the affected code paths, cites correct line numbers in the source files, reuses an established test fixture pattern (`mkdtempSync` + `reindex(...)`), and explicitly disavows scope creep into the parallel reindex-OOM and silent-failure issues. No iteration required.

## Dimension Verdicts

### 1. Completeness — PASS

Phase 1 is fully defined with four concrete tasks (parser, db, reindex hand-off, end-to-end test). Each task names exactly the file(s) it touches, the function(s) it modifies, and the new behavior. No phase or task is left under-specified.

### 2. Feasibility — PASS

Spot-checked all referenced files and line ranges against the working tree:
- `plugin/ralph-knowledge/src/parser.ts` lines 91-144 contain `parseDocument()` with the exact frontmatter-extraction block the plan extends. Verified `memory_tier` is absent from current extraction.
- `plugin/ralph-knowledge/src/db.ts` lines 186-198 contain the schema v3 ALTER TABLE migration with the CHECK constraint as described.
- `plugin/ralph-knowledge/src/db.ts` lines 223-231 contain the `upsertDocument()` INSERT/UPDATE clauses. Verified `memory_tier` is absent from both column lists.
- `plugin/ralph-knowledge/src/db.ts` lines 477-486 contain `getMemoryTier()`. Verified it reads the column with a v2-compat guard.
- `plugin/ralph-knowledge/src/reindex.ts` lines 135-144 contain the exact `db.upsertDocument({...})` payload the plan extends with `memoryTier: parsed.memoryTier`.
- `plugin/ralph-knowledge/src/__tests__/reindex.test.ts` already establishes `mkdtempSync` + `writeFileSync` + `await reindex([dir], dbPath)` (lines 127, 143, etc.) — the new E2E test reuses this pattern verbatim.
- `plugin/ralph-knowledge/src/__tests__/db.test.ts` line 609 already has a `describe("schema v3: memory_tier column", ...)` block with hand-crafted INSERTs — the plan correctly notes this verifies the *filter* not the *write path*.

### 3. Clarity — PASS

Success criteria use the canonical `- [ ]` checkbox format, partitioned into Automated Verification (`npm run build`, `npm test`) and Manual Verification (the local-corpus reindex and `dream-now` round-trip, both correctly gated on GH-907). Each task's acceptance criteria is testable: the parser tests name the spy (`vi.spyOn(console, 'warn')`), the db tests name the assertion (`getMemoryTier(id) === 'raw'`), and the E2E tests name the SQL belt-and-suspenders (`db.db.prepare("SELECT memory_tier FROM documents WHERE id = ?")`).

### 4. Scope — PASS

`What We're NOT Doing` is explicit and well-bounded:
- Defers GH-907 (reindex OOM) — independent fix scope, no shared files
- Defers GH-908 (silent-failure surfacing) — blocked on GH-907
- Refuses to promote `memory_tier` to a required `DocumentRow` field — protects existing call sites
- Refuses to add a new `getMemoryTier()` method — one already exists
- Refuses to migrate existing rows — natural reindex will repopulate
- Refuses to introduce a config schema for tiers — three values stay hardcoded

The boundary between this plan and the parallel issues is unambiguous.

### 5. Dispatchability — PASS

Each of the four tasks carries the required dispatch envelope:

| Task | files | tdd | complexity | depends_on | acceptance |
|------|-------|-----|------------|------------|------------|
| 1.1  | parser.ts (modify) | true | low | null | 5 unit-test scenarios listed |
| 1.2  | db.ts (modify) | true | low | [1.1] | 5 unit-test scenarios listed (incl. COALESCE re-upsert) |
| 1.3  | reindex.ts (modify) | false | low | [1.1, 1.2] | 1-line edit + tsc clean |
| 1.4  | reindex.test.ts (modify) | true | medium | [1.1, 1.2, 1.3] | 4 E2E scenarios, no `:memory:`, no hand-crafted INSERT |

A subagent executing any single task has enough context to implement and self-verify without re-reading the rest of the plan. The intra-phase `depends_on` chain (1.1 → 1.2 → 1.3 → 1.4) correctly forces the natural fix-then-forward-then-test sequence.

The COALESCE-on-update detail in Task 1.2 is a nice touch — it prevents a re-upsert without an explicit tier from clobbering an existing `'raw'` row back to `'doc'`. This handles the realistic case where `parseDocument()` may someday be called by a path that doesn't carry tier info.
