# Plan Critique: GH-1285 — Typed MCP Tool Surface for kubectl Autoremediation

## Verdict

**NEEDS_ITERATION** — The plan is structurally strong and security-aware, but contains one factual error about the current state of the codebase (claim that `agents/sre-fixit.md` does not exist when in fact it does), plus a handful of dispatchability and consistency gaps that would cause friction or rework if an implementation agent took the plan literally.

The plan is close to approval-ready; the gaps below are surgical, not foundational.

## Dimension Scores

### 1. Completeness — PASS (with one note)

All 6 phases are defined, each maps 1:1 to a sub-issue, and every phase has concrete file paths and task-level acceptance criteria. The Shared Constraints block (sections 1–7) centralizes the non-negotiable invariants so individual phases don't drift. Phase dependency graph is explicit (`depends_on: [phase-N]`) and matches the dependency chain documented in #1285's split comment.

**Note**: The plan's "Current State Analysis" claims `agents/sre-fixit.md` does NOT exist ("Phase 6 creates the file from scratch"). It does exist — see `plugin/ralph-hero/agents/sre-fixit.md` (the refusal-only stub shipped with GH-1270 watcher work). Phase 6 should be reframed as "modify" rather than "create", and Task 6.1 should explicitly account for replacing the refusal-only body and tightening `tools:` rather than authoring a new file alongside an existing one. The existing file already explicitly anticipates GH-1285 landing — that context should be preserved or intentionally retired.

### 2. Feasibility — FAIL

Verified the existing codebase via direct inspection:

- `plugin/ralph-hero/mcp-server/src/tools/` exists with 15 tool modules. `sre-tools.ts` is correctly absent. **PASS**
- `plugin/ralph-hero/mcp-server/src/lib/` exists with 36 lib modules. `kubectl-exec.ts` is correctly absent. **PASS**
- `plugin/ralph-hero/mcp-server/src/index.ts` follows the `register*Tools(server, client, fieldCache)` pattern at lines 508–547; the plan's wiring task (1.3) matches the actual conventions. **PASS**
- `plugin/ralph-hero/mcp-server/src/tools/issue-tools.ts` line 54–57 confirms the `(server, client, fieldCache)` signature shape the plan prescribes. **PASS**
- `plugin/ralph-hero/agents/sre-fixit.md` **EXISTS** as a refusal-only stub. Frontmatter shows `tools: Read, mcp__plugin_ralph-hero_ralph-github__ralph_hero__create_comment, mcp__plugin_ralph-hero_ralph-github__ralph_hero__save_issue`. **FAIL** — the plan asserts this file does not exist.

The feasibility failure is the existing-file mismatch. Everything else lines up cleanly with the codebase.

A secondary feasibility concern: Task 6.1 specifies the agent must include `mcp__plugin_ralph-hero_ralph-github__ralph_hero__get_issue` and `mcp__plugin_ralph-hero_ralph-github__ralph_hero__create_comment` but drops `save_issue`. The refusal-only stub uses `save_issue` to move the issue to "Human Needed" — if the new agent inherits the escalation protocol from the existing file, it will need `save_issue` too. Either the allowlist needs `save_issue` added, or Task 6.1 must explicitly state that the new agent does not escalate via `save_issue` (and instead delegates that to the orchestrator).

### 3. Clarity — PASS

Success criteria are highly specific and testable:

- Phase 1 "Verification" enumerates `npm run build`, `npx vitest run src/__tests__/sre-tools.test.ts`, and grep-based invariant checks
- Phase 2 establishes the canonical adversarial-test pattern with named per-class tests (matches Shared Constraint #4)
- Phases 3–5 explicitly defer to phase 2's pattern, reducing repetition without losing the per-phase checklist
- Top-level "Verification" section (lines 99–105) gives the integration-level success grep audits
- Forbidden-flag rejection list is enumerated as a `FORBIDDEN_FLAGS` constant (line 144) — exact, not hand-waved

**Minor clarity note**: Phase 3 Task 3.1's argv spec uses a JS template literal: `` ["rollout", "restart", "--namespace", namespace, \`deployment/${deployment}\`] ``. Every other argv spec is a plain array literal; this is the only one that interpolates. The note that this is "safe because the regex forbids `/` in the suffix" is correct, but it's the lone exception to the "no string interpolation" rule established in Shared Constraint #1's spirit. Worth a one-sentence callout in Phase 3's overview so an implementer doesn't flag-fight the precedent.

### 4. Scope — PASS

"What We're NOT Doing" (lines 107–116) is explicit and well-bounded. The 8 items name what is in scope of GH-1285's successor work (wiring into watcher, RBAC, multi-cluster) versus what is permanently outside the design (force flags, bulk operations, free-form flag pass-through). The boundary with GH-1270 is clear: phase 6 creates/updates the agent file; wiring into the watcher dispatch is explicitly deferred.

### 5. Dispatchability — PARTIAL FAIL

Each task has `files`, `tdd`, `complexity`, `depends_on`, and `acceptance` fields — matching the dispatchable-task schema. The depends_on graph is clean (phase 1 → phases 2–5 in parallel → phase 6).

Issues that would cause a dispatched implementation agent to stall or rework:

1. **Phase 6 task "create" vs "modify" mismatch**: A dispatched agent reading `files: plugin/ralph-hero/agents/sre-fixit.md (create)` will hit a file-already-exists guard and stop. Should be `(modify)`.

2. **Drain happy-path argv shape under-specified**: Task 5.1 says argv "always prefixes with `["drain", node, "--ignore-daemonsets"]`" but Phase 5 Task 5.2's happy-path assertion shows `["drain", "node-1", "--ignore-daemonsets"]` — no namespace. `kubectl drain` takes a node name (cluster-scoped), so this is technically correct, but a node-level drain doesn't go through `--namespace`. Worth adding a one-line note that nodes are cluster-scoped to head off an implementer adding `--namespace` reflexively after writing four namespace-scoped tools in phases 2–4.

3. **Tool name prefix double-encoding**: The plan uses `ralph_hero__sre__scale` (lines 67, 408). The MCP server prefix convention in CLAUDE.md is `ralph_hero__<tool>` (single double-underscore separator). The agent allowlist line in Task 6.1 uses `mcp__plugin_ralph-hero_ralph-github__ralph_hero__sre__scale` — note the four-segment path with the `mcp__plugin_…` prefix that Claude Code prepends. The plan is internally consistent (tool names use `__sre__` as a namespace inside the `ralph_hero__` prefix), but Shared Constraint #6 wording ("The double-underscore matches the existing `ralph_hero__` prefix convention") implies it's the same convention, when in fact it's a new namespacing pattern. Worth one extra sentence saying "this introduces a `sre__` sub-namespace inside the existing prefix" so reviewers don't trip on this.

4. **Phase 5 forbidden-flag invariant test missing `--cascade=foreground`**: Task 5.2's invariant test says "argv never contains `--force, --delete-emptydir-data, --grace-period=0`". The Shared Constraint #3 list has four forbidden flags including `--cascade=foreground`. The omission is presumably because drain doesn't naturally produce `--cascade=foreground`, but the test should still assert all four are absent so it serves as a regression gate identical to phases 2–4.

5. **Phase 6 allowlist incomplete for the documented escalation protocol**: As noted in Feasibility — if the new agent escalates to Human Needed (the natural extension of the existing refusal-only behavior), it needs `save_issue` in the allowlist. The plan needs to either (a) add `save_issue`, or (b) explicitly state escalation is no longer this agent's responsibility.

## Recommended Iteration Actions

Listed in priority order; all surgical:

1. **Fix the "create vs modify" mismatch in Phase 6** — change Task 6.1's `files: plugin/ralph-hero/agents/sre-fixit.md (create)` to `(modify)` and update the phase overview to reflect that the existing refusal-only stub is being retired/replaced.
2. **Decide the `save_issue` question for sre-fixit** — either add it to Task 6.1's allowlist (with one sentence explaining it's needed for "Human Needed" escalation) or document that escalation moves to the orchestrator.
3. **Update "Current State Analysis"** to acknowledge `agents/sre-fixit.md` exists and explain the relationship between the existing stub and the new file.
4. **Add the missing `--cascade=foreground` assertion** to Phase 5 Task 5.2's invariant test.
5. **Add a one-line note in Phase 3** explaining the `deployment/<name>` template-literal exception to the "array literal only" pattern.
6. **Add a one-line note in Phase 5** explaining that `kubectl drain` is cluster-scoped (no `--namespace`) so the missing `--namespace` in Task 5.2's happy path is intentional.
7. **Clarify the `sre__` sub-namespace convention** in Shared Constraint #6 so reviewers don't mis-read it as the existing `ralph_hero__` convention.

None of these require new research. All are doc edits to the plan file. After they land, the plan reads as approval-ready.

## Strengths Worth Preserving

- The Shared Constraints block at the top is excellent — it pulls non-negotiable invariants out of individual phases and makes them the contract.
- The "four named adversarial test classes" (Constraint #4) maps directly to the four bypass classes from PR #1278's review, so future regressions point at the originating class.
- The defense-in-depth design (typed Zod schemas + forbidden-flag check in the exec helper) is exactly the right pattern for a security-critical surface.
- The dependency graph (scaffold → ops in parallel → agent) is the cleanest possible decomposition of the work.
- The "What We're NOT Doing" list is unusually thorough and pre-empts scope creep.
