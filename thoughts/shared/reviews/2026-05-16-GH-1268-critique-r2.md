## Minor Observations (Non-Blocking)

These do not affect the verdict but are worth noting for the implementer:

1. **Team-name vs. skill-dir mapping.** The smoke test Tests C1-C5 acceptance (line 282) says "contains `team: <expected-team-name>`" but does not enumerate the mapping inline. The implementer must cross-reference Phase 3 Task 3.1-3.5 to derive: `hero/` → `team: builders`, `watch/` → `team: watchers`, `scouts/` → `team: scouts`, `memorykeepers/` → `team: memorykeepers`, `caretake/` → `team: caretakers`. A short inline table in Task 4.1 would save a second hop, but the information is fully available in the same plan. Not blocking.

2. **Test E cleanup discipline.** Task 4.1 Test E (line 284) says "Cleanup the tempfile after the test." Recommend the smoke use `trap 'rm -f "$tempfile"' EXIT` rather than an inline `rm` so a failed assertion does not leak a tempfile. The plan does not specify this and the implementer should choose. Not blocking.

3. **`set -euo pipefail` interaction with `jq` failure modes.** With `set -e`, a `jq` parse failure on input would terminate the hook with a non-zero exit. The plan asserts "Final `exit 0` is explicit" (Task 2.1 line 156). Since the hook builds the JSON via `jq -n` from a `$ctx` arg (not by parsing untrusted JSON), this is safe in practice — `jq -n` cannot fail on the argument shape used here. Worth a brief note in the header comment if the implementer wants to be explicit. Not blocking.
