# Plan Critique: GH-967 — record-activity.sh stdin JSON fix

## Summary

Single-issue, single-phase XS bug fix to make `record-activity.sh` read its
metadata from stdin JSON (the actual Claude Code hook contract) instead of
never-set environment variables. The plan is well-researched, references real
code, and decomposes cleanly into one script-rewrite task plus one test-update
task with four new regression tests.

**Verdict: APPROVED** with one implementation note (see Feasibility).

## Dimension Scores

### 1. Completeness — PASS

- One phase, two tasks, each with `files` / `tdd` / `complexity` / `depends_on` /
  `acceptance` populated.
- Acceptance bullets are concrete: exact `grep` patterns to verify env-var
  removal, exact JSON payloads to pipe, exact field assertions.
- Manual smoke-test command included verbatim:
  `echo '{...}' | RALPH_ACTIVITY_DIR=/tmp/test-activity bash plugin/.../record-activity.sh tool_called`
- Hook-wiring claims (`SessionStart` at hooks.json:30, `PostToolUse` at :165)
  verified against the real file.
- Live evidence in plan body (38 events at write time) verified — the file now
  has 181 lines, all with the same `target.tool: "unknown"` symptom.

### 2. Feasibility — PASS (one implementation gotcha to call out)

- All referenced files exist:
  - `plugin/ralph-hero/hooks/scripts/record-activity.sh` (the buggy script)
  - `plugin/ralph-hero/hooks/scripts/hook-utils.sh` (canonical pattern)
  - `plugin/ralph-hero/hooks/scripts/post-github-validator.sh` (reference impl)
  - `plugin/ralph-hero/hooks/scripts/outcome-collector.sh` (reference impl)
  - `plugin/ralph-hero/hooks/scripts/__tests__/record-activity.test.sh` (test target)
- The decision NOT to source `hook-utils.sh` is sound — it sets
  `set -euo pipefail` and its `block`/`warn` helpers exit 2, which would
  break the "exit 0 always" guarantee on which the entire activity log
  depends. The plan correctly chooses to replicate the *pattern* (read stdin,
  jq extract) without inheriting the strictness.
- The `${raw##*:}` agent-type strip mirrors
  `hook-utils.sh::get_agent_type` exactly.

**Gotcha (not a blocker):** The proposed `extract()` helper in Task 1.1
acceptance line 154 is:

```bash
extract() { echo "$INPUT" | jq -r "$1 // \"$2\"" 2>/dev/null || echo "$2"; }
```

When `$INPUT` is the empty string (the explicit empty-stdin case the plan
adds a test for), `echo "" | jq -r '.foo // "default"'` exits 0 with empty
output — so the `|| echo "$2"` fallback **never fires** and the function
returns an empty string, not the default. I verified this end-to-end:

```
$ INPUT=""; echo "$INPUT" | jq -r '.tool_name // "unknown"'; echo "rc=$?"
                                  # (blank line)
rc=0
```

This means the new test "empty stdin: graceful fallback to defaults" (Task 1.2
acceptance line 180, which asserts `.target.tool == "unknown"`) will **fail**
if Task 1.1 is implemented exactly as written. The fix is one of:

1. Default `INPUT` to `{}` after `cat`:
   `INPUT=$(cat 2>/dev/null); [ -z "$INPUT" ] && INPUT="{}"`
2. Guard `extract` with an empty check:
   `extract() { [ -z "$INPUT" ] && { echo "$2"; return; }; echo "$INPUT" | jq -r ... ; }`

Either fix is a one-line change. Because Task 1.2 is marked `tdd: true`, the
TDD loop will catch this when the empty-stdin test is run — but it's worth
flagging up front so the implementer doesn't burn a debugging cycle.

## Minor Observations (non-blocking)

- The plan notes the bash test suite isn't in CI today and flags it as a
  follow-up. That's the right level of disclosure — solving the CI gap is
  out of scope for an XS bug fix.
- `basename "/"` returns `/`, not `unknown`. If a hook ever delivered
  `cwd: "/"` the project field would be `/`. Unrealistic enough to not
  matter; not worth iterating on.
- The plan extracts `skill_name` from stdin even though the `skill_invoked`
  event is dead in production. This is correct — the test suite still
  exercises that code path, and keeping it test-addressable costs nothing.

## Recommendation

APPROVE. The empty-stdin gotcha is a real flaw in the proposed `extract()`
helper definition, but it will be caught by the very test the plan adds for
that case, the fix is trivial, and asking for re-planning on a one-line
adjustment to an XS bug fix would slow down a high-signal repair.

The implementer should treat the gotcha section above as a heads-up: if the
empty-stdin test fails, default `INPUT` to `"{}"` after the `cat` line.
