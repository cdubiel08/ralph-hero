# Plan Review: GH-1189 — F4b pr-agent PR description from diff via delegation

## Verdict

APPROVED.

This plan correctly identifies itself as the second Wave-3 production integration of the delegation pattern (sibling to F4a / #1188). It picks the right delegation site (`## Summary` composition inside Step 5 of `skills/ralph-pr/SKILL.md`) — the one place in `ralph-pr` that produces free-form text-for-Claude-to-paste-into-an-argument and is bounded enough to be safe to delegate. Every file path the plan references on the read/modify side exists on `main` or on the `feature/GH-1188` branch (F4a). The mutation-step preservation (`gh pr create` is never delegated) is enforced by three independent assertions: a grep guard, a manual readthrough, and a placement constraint ("before the `gh pr create` heredoc, never after, never inside an `if OUTPUT=$(...)` guard"). The no-regression invariant is testable and tight.

## Key Decisions Verified

1. **Skill calls `ralph-delegate.sh --task pr_description` only, never `openai-compat.sh` directly** — VERIFIED. Plan's Task 1.1 acceptance asserts `grep -c 'openai-compat.sh' returns 0` post-impl. Aligns with `delegation-conventions.md` rule that "the adapter is internal; skills/agents always go through the wrapper."
2. **`gh pr create` is never delegated** — VERIFIED. Issue acceptance criterion #5 is enforced by three independent assertions: (a) `grep -c 'gh pr create' SKILL.md >= 2` (Step 3a + Step 5, both preserved); (b) "the bash block calling the wrapper appears BEFORE the `gh pr create` heredoc, never after, and `gh pr create` is never invoked from within an `if OUTPUT=$(...)` guard"; (c) Smoke 6 manual readthrough as the human-verification version of the grep guards.
3. **Bash-level shape guards (length < 1024 + no leading `#`); bad shape triggers fallback** — VERIFIED. Shared Constraint #8 documents this with explicit rationale: this is the F4b analog of F4a's `jq -e .ranked` guard — same purpose (caller validates shape because the wrapper is text-in/text-out and does not understand task-specific schemas), different mechanism (no JSON, so plain-bash byte checks). Test 2 (oversized) and Test 3 (heading prefix) in the bats suite cover the two distinct shape-failure branches separately. Both attribute the failure correctly to the skill, not the wrapper (audit-log records `status=ok` because the HTTP layer succeeded; the skill privately discards the un-usable output).
4. **Threshold gate: delegation fires only when ≥2 files OR ≥20 lines** — VERIFIED. Shared Constraint #10. Acknowledged as hard-coded in v1, configurable later if Wave-3 telemetry shows the wrong cut. Test 7 in the bats suite (Task 1.3 acceptance) covers the below-threshold path with a byte-equality assertion on the audit log file (`wc -c` pre/post). This is a strict improvement over F4a, which documented its threshold gate (≥5 candidates) but did not unit-test it.
5. **8 KB prompt size cap, truncate-then-fallback** — VERIFIED. Shared Constraint #9. The plan documents the truncation order (cap the `Recent commits:` block first via `head -c 4096`, re-check, then fall back to native if still over). Chosen so a typical 8k-context window does not need to truncate from the back, which would drop the assistant instructions.
6. **Per-task override env-var name resolution: `pr_description` → `PR_DESCRIPTION`** — VERIFIED. F1's `_resolve_task_var` at `ralph-delegate.sh:147-162` uses `tr '[:lower:]-' '[:upper:]_'` which preserves the underscore in `pr_description` and uppercases the letters, yielding `RALPH_DELEGATE_PR_DESCRIPTION_URL/MODEL`. No code change needed; just consistent `--task pr_description` from the skill.
7. **Soft-prerequisite F4a (#1188) merged on a feature branch but not yet on main** — VERIFIED. F4a's commit `cefb9189` is on `feature/GH-1188` (not yet PR'd or merged to main as of plan authoring). The plan correctly treats F4a as a structural template (read-only references for the bats and agent-body patterns) without making F4b's impl depend on F4a having landed on main first. F4b's bats file can be authored from scratch using F1's stub pattern as the primary template, with F4a's bats file as a 1:1 helper-function template if accessible; if not accessible, F4a's patterns are also documented in the plan's prose (Current State Analysis section). The plan handles both ordering scenarios (F4a merges first → F4b benefits from the precedent file; F4a doesn't → F4b is still complete on its own).
8. **No-regression: with `RALPH_DELEGATE_ENABLED` unset, skill is bit-identical** — VERIFIED. Shared Constraint #5 and Test 5 in the bats suite (Task 1.3 acceptance) assert byte-identical audit-log file (`wc -c` pre/post) when the env var is unset. The wrapper's 126-no-log invariant (lines 192-198 of `ralph-delegate.sh`) makes this trivially achievable. The skill's bash block's `case "$rc" in 126) ;;` (empty body) ensures no `delegation:` note is printed on 126 either.
9. **Substitution mechanism preserves heredoc quoting** — VERIFIED. The existing Step 5 heredoc uses `<<'PREOF'` (quoted PREOF, no variable expansion). The plan's substitution method (write heredoc to tempfile + `sed -i` for the placeholder + `gh pr create --body-file <tempfile>`) preserves the existing quoting behavior — critical because the heredoc contains backticks and other shell metacharacters that would expand if the heredoc were unquoted. Task 1.1 acceptance line documents this choice explicitly.

## Minor Observations (Not Blocking)

These are nitpicks the impl agent may discover during execution. None require iteration:

1. **F4a not on main at plan authoring** — The plan was authored while F4a sits on `feature/GH-1188`. The impl agent should treat F4a references (the agent file, the bats file) as structural templates read from the feature branch rather than from main, or rebuild the templates from F3 + F1 directly if F4a's branch is not accessible. The plan handles both cases in its prose, so no iteration needed.
2. **`mktemp -t pr-description-XXXXXX` prefix follows F3/F4a convention** — F3 uses `delegate-test-XXXXXX`, F4a uses `locator-XXXXXX`; F4b's `pr-description-XXXXXX` continues the pattern. Task 1.1's smoke-6 assertion (`find /tmp -name 'pr-description*' -mmin -5 | wc -l == 0`) is keyed to this prefix.
3. **"Caller field is best-effort" caveat** — Shared Constraint #13 documents that `caller=ralph-pr` (or `pr-agent`) in the audit log depends on the runtime `RALPH_HOOK_INPUT.tool_input.caller_skill` arriving with the right field. Inherits the same caveat as F4a's Shared Constraint #12. If the field arrives as `unknown`, it's a hook-context bug to address in F5 or a follow-up, not in F4b.
4. **3-PR eval baseline of "8 of 12 cells match or beat" is a soft target** — Plan correctly frames this as a calibration metric, not a merge gate. Impl agent should not be tempted to block on it. The judgment is recorded in an issue-1189 comment for transparency, not as a CI gate.
5. **Heredoc-substitution via `--body-file` is a minor mechanism change** — Today's Step 5 uses `gh pr create --body "$(cat <<'PREOF' ... PREOF)"` (inline body via command substitution). F4b's plan switches to `gh pr create --body-file <tempfile>` to allow `sed -i` substitution on the file. Both are equivalent in `gh` CLI; the switch is a clean mechanism change, not a semantic one. Document briefly in the impl commit message so reviewers understand why the `--body` argument shape changed.
6. **Total file growth budget of 150 added lines is reasonable** — Plan's "if the section grows past 150 added lines, the section is too verbose — trim the bash block comments" guidance is tighter than F4a's "40-80, max 100" because F4b's skill body needs both the threshold-gate prelude AND the heredoc-substitution mechanism, which F4a didn't need.
