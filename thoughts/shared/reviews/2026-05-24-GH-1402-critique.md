## Failures

- **Phase 7 §2 mis-describes the file it edits (FAIL — Verification quality + File ownership).** Phase 7 §2 says it will "Update the `RALPH_TRIAGE_ACTION` allowlist regex" in `triage-postcondition.sh`, and its automated verification asserts `grep -nE 'ROUTE_TO_RESEARCH|...' triage-postcondition.sh` returns ≥3 and `grep '\bKEEP\b' triage-postcondition.sh` returns 0. The real `triage-postcondition.sh` **does not reference `RALPH_TRIAGE_ACTION` and contains no `KEEP` token** — it is a Stop hook that greps the transcript for `^TRIAGED (valid|duplicate|canceled|needs-split|skipped)|^Queue empty\.`. So (a) there is no allowlist regex in the hook to edit; (b) `grep KEEP` already returns 0 today, making that AV vacuous; (c) the real change required is rewriting the `TRIAGED (valid|...)` transcript pattern to accept `TRIAGED routed → <state>`. The `RALPH_TRIAGE_ACTION` allowlist actually lives in `triage.md`. The phase as written is not implementable as specified.
- **Estimate sanity (FAIL).** GH-1402 is estimated **S**; the plan body declares "Implementation tier: M" (line 140) and `## Files Affected` totals 10 new + 13 modified files across 7 phases, including 5 new bash test files, a new lint script, a new hook script, and an existing hook edit. An S issue cannot carry an M, 7-phase, 23-file plan with new hooks/tests. Re-estimate the issue to M (matching the plan's own tier + the user's expansion commits) or split Phases 6-7 into separate issues.

Keep the `RALPH_TRIAGE_ACTION` allowlist edits under the `triage.md` §Step 5 changes (Phase 7 §1) where that allowlist actually lives.
