# Plan Critique: GH-1268 SOUL Framework + SessionStart Hook

## Summary

VERDICT: NEEDS_ITERATION

The plan is well-structured, scoped tightly, and correctly identifies dependencies between its four phases. Frontmatter, references, success criteria, and "What we're NOT doing" sections are all present and specific. However, the plan's Phase 2 (the load hook itself) contains a load-bearing technical claim that contradicts the existing SessionStart-context-injection pattern in this repo, and Phase 4 inherits the same defect via its acceptance assertions. Both must be corrected before implementation begins — otherwise the hook will run silently, the smoke test will pass on a contract that does not reach the model, and the entire feature will ship as a no-op in production.

## Dimension Scores

### Completeness — PASS
All four phases are defined with specific file paths and per-task acceptance lists. Phase ordering and inter-phase dependencies are explicit ("Creates for next phase" annotations on each phase). Task 2.1, 3.1–3.5, and 4.1 each enumerate verifiable acceptance checks. Phase 4 includes both automated (`bash smoke.sh exits 0`) and manual verification (graceful-failure mode when a SOUL file is deleted).

### Feasibility — FAIL
All *referenced* files exist on disk (verified):

- `plugin/ralph-hero/skills/STYLE.md` — present
- `plugin/ralph-hero/skills/shared/artifact-comment-protocol.md` — present
- `plugin/ralph-hero/hooks/scripts/set-skill-env.sh` — present
- `plugin/ralph-hero/skills/hero/SKILL.md` — present
- `plugin/ralph-hero/scripts/cos/smoke.sh` — present (pattern reference)
- `plugin/ralph-hero/scripts/cos/self-improve-smoke.sh` — present

All creation targets are correctly absent. Existing convention checks pass.

**However**, the plan's central runtime claim is wrong. Task 2.1 acceptance states:

> If the candidate exists, writes the file contents to stdout (the runtime injects stdout into the model's system context).
> Does not mutate `$CLAUDE_ENV_FILE` — emits SOUL content via stdout only.

This is **not** how Claude Code SessionStart context injection works in this repo. The existing precedent — `plugin/ralph-hero/hooks/scripts/superpowers-bridge-session.sh` — wraps the additional context in a JSON envelope and writes the JSON to stdout:

```bash
jq -n --arg ctx "$CONTEXT" '{
  hookSpecificOutput: {
    hookEventName: "SessionStart",
    additionalContext: $ctx
  }
}'
```

Raw `cat` of SOUL file contents to stdout will be ignored by the runtime — it is not interpreted as system context. The hook will silently appear to work (exit 0, no error), the smoke test as written will pass (it asserts stdout contains `team: <name>`, which a raw `cat` does satisfy), but the SOUL body will never reach the model's system prompt in a live session. The feature ships broken.

Phase 4 Tests C1–C5 inherit this defect. Asserting `stdout contains 'team: hero'` is exactly what a `cat` of frontmatter produces — but the actual SessionStart contract requires JSON-envelope output. The smoke needs to assert the stdout is parseable JSON with `.hookSpecificOutput.additionalContext` containing the SOUL body, not raw text.

## Issues to Address

1. **(Blocker) Fix the SessionStart stdout contract in Task 2.1.** Replace "writes the file contents to stdout" with "emits a JSON envelope `{ hookSpecificOutput: { hookEventName: 'SessionStart', additionalContext: <SOUL body> } }` to stdout, using `jq -n --arg ctx \"$(cat $SOUL_PATH)\" ...` (or equivalent). See `plugin/ralph-hero/hooks/scripts/superpowers-bridge-session.sh` for the canonical pattern." Also update the Overview paragraph for Phase 2, the Desired End State checklist item, and Phase 2's automated-verification block accordingly. Add `command -v jq >/dev/null` as an implicit dependency or document a `jq`-free fallback.

2. **(Blocker) Update Phase 4 Tests C1–C5 and Test D to assert the JSON envelope shape.** Current assertions (`stdout contains 'team: hero'`, `stdout contains '## How you talk'`) will pass for either raw-cat or JSON-envelope output, masking the bug fixed in Issue #1. The smoke must parse stdout as JSON and assert `.hookSpecificOutput.hookEventName == "SessionStart"` and `.hookSpecificOutput.additionalContext` contains the expected substring. Without this update, the contract binding the plan claims is not actually enforced.

3. **(Minor) Clarify whether `load-team-soul.sh` should also export `RALPH_SOUL_LOADED=<team>` to `$CLAUDE_ENV_FILE`** for downstream hooks to detect that a SOUL was injected. The existing pattern (`superpowers-bridge-session.sh` sets `RALPH_SUPERPOWERS_BRIDGE=true`) suggests this is convention — and Features B/C/F/G may want to assert SOUL was loaded. The plan's "Out of Scope" rules out mutating `$CLAUDE_ENV_FILE`; consider whether this is still the right call given the existing pattern, or document why the SOUL hook deliberately diverges.

## Recommendation

Iterate on Phase 2 and Phase 4 to align with the existing SessionStart context-injection contract. Once Tasks 2.1, 2.2, and 4.1 reflect the JSON-envelope shape (and the smoke test asserts the envelope, not raw text), the plan is implementation-ready. Phase 1 and Phase 3 are unaffected and can stand as-is.

Re-run `/ralph-plan 1268` to update the plan with the corrected runtime contract.
