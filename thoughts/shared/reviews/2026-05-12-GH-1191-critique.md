# Plan Critique: GH-1191 — F5 Delegation Telemetry & Cost Tracking

## Summary

**VERDICT: APPROVED**

The plan is well-scoped, technically grounded, and dispatchable. All referenced
files exist; all claimed line numbers are accurate. The author preserves the
F1 audit-log shape (no producer changes), reuses three existing precedents
(`snapshots.ts`, `activity.ts`, `activity/logrotate.sh`), and explicitly

## Decisions the plan made (and why they're correct)

1. **Minimal size-based rotation** rather than logrotate-in-README. The
   activity log already establishes the rotation-script-plus-launchd-template
   convention. Picking the same shape keeps operator mental model uniform.

2. **`bytesIn`/`bytesOut` instead of synthesized tokens**, with `tokens: null`
   and a top-level `tokensReason` note. The producer (F1) does not capture
   `usage.prompt_tokens` today; fabricating tokens from bytes would
   poison downstream cost math. The forward-compat note ("reader will
   detect that field when present") leaves the door open for a future F1
   patch without breaking this surface.

3. **Implicit v1 schema check by required-field presence**
   (`{ts, task, status, ms}` must be present). The current F1 lines lack a
   `schemaVersion` field, so a literal version check would reject every
   real line. The required-field gate is a sensible interim that
   `snapshots.ts` already validated as a pattern.

## Minor observations (non-blocking)

These are notes for the implementer, not gating issues:

- **Async vs sync fs.** Task 1.1 mandates `node:fs/promises` to mirror
  `snapshots.ts`. Worth confirming the MCP tool's async signature accepts
  this; `activity.ts` uses sync `fs.readFileSync`. Both are precedented in
  this repo — the plan picks the async one. Either works; the explicit
  choice is fine.
- **`--delegation` arg parsing in justfile.** Task 1.3 says
  "pure bash conditional inside the recipe — no Justfile-language tricks."
  Worth flagging that the existing recipe uses
  `_args={{quote(args)}}; set -- $_args`, so the implementer should pattern-
  match via `case "$*" in *--delegation*)`. This is implicit in the plan
  but spelling it out would speed dispatch.
- **launchd template path placeholders.** Task 1.5 says
  `/Users/$USER/...` placeholders. The activity-rotate template
  (`com.ralph.activity-rotate.plist.template`) is the precedent —
  implementer should copy its exact placeholder convention rather than
  invent a new one.

None of these block approval; they would be one-line clarifications
the implementer can resolve from the precedent file directly.
