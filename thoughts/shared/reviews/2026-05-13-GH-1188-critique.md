## Minor Observations (Not Blocking)

These are nitpicks the impl agent may discover during execution. None require iteration:

1. **Stale "in flight on feature/GH-1187" references (lines 72, 315-317)** — The plan was authored before F3 merged this session. The impl agent should treat these as historical context, not gating conditions.
2. **`mktemp -t locator-XXXXXX` prefix not specified explicitly** — F3's reference skill uses `mktemp -t delegate-test-XXXXXX`; the plan's bash-block spec uses unprefixed `mktemp` (line 284 acknowledges this with the "loose `find /tmp` assertion" caveat). Recommend mirroring F3's prefix pattern (`mktemp -t locator-XXXXXX`) for clean teardown — but acceptance #2's wording does not block this either way.
3. **"Caller field is best-effort" caveat** — Shared Constraint #12 documents that `caller=codebase-locator` in the audit log depends on the runtime `RALPH_HOOK_INPUT.tool_input.caller_skill` arriving with the right field. If F1's bats test 8 and F3's smoke 1 already verified this works end-to-end, F4a inherits the same behavior. If the smoke check fails, it's a hook-context bug to address in F5 or a follow-up, not in F4a.
4. **Eval baseline of 60% mean overlap is a number, not a verdict** — Plan correctly frames this as a calibration metric, not a merge gate (line 126, line 237, line 283). Impl agent should not be tempted to block on it.
