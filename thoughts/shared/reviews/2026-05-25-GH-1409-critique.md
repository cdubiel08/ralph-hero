# Review: GH-1409 — Director routes `blocked:*` labels (iteration 1)

## Plan Reference

[`thoughts/shared/plans/2026-05-25-GH-1409-director-blocked-label-routing.md`](../plans/2026-05-25-GH-1409-director-blocked-label-routing.md)

## Strengths

- Clean 2-phase split by surface; `blocked:* NOT consumed` decision sound and well-justified; AC3 "falls out of ordering" reasoning correct; iOS-sentinel renumber spot caught; prefix-vs-exact match nuance captured; mode-mapping nuance flagged.

## Gaps

- **File ownership:** the two `event-classes.md` copies are NOT identical — slim uses `ralph:` entrypoints, legacy uses `ralph-hero:`. The plan's "same edit applies to both" / "no drift" is false; new rows must follow each file's prefix convention. Also `label-routing.md` (caretake's default-event table) is an unacknowledged sibling with no `blocked:*` rows.
- **Verification quality:** "diff the two — no drift" is wrong (copies pre-diverge); no check covers the legacy inline `**Priority N**` headers or the dispatch-arg shape.
- **Risk coverage → escalated to FAIL (below).**
- **Linked research:** the flawed `--issue NNN` arg shape was inherited from the issue body unexamined.

## Failures

- **Dispatch target ignores `--issue NNN` — it's a board-wide sweep.** `watch-pr.md`/`watch-upstream.md` `list_issues(...)` the whole parked set and process all of it; neither reads a `TARGET_ISSUE`. So `caretake --mode watch-pr --issue NNN` runs the full sweep regardless of `NNN`. This invalidates the plan's "single-item routing" framing. Must either drop `--issue NNN` (honest: an event-driven board-wide sweep) or descope.
- **Legacy `director/SKILL.md` inlines its own Priority-1/2/3 headers + a "Priority 3" sentinel note** — more renumber spots than Phase 2 enumerated. And both classify bodies dispatch a bare `NNN` (`args="NNN"`); the legacy body explicitly says "bare number `NNN` (not `--issue NNN`)" — directly contradicted by the new `--mode …` arg shape. Phase 2 must enumerate these spots and reconcile the convention.

## Recommended Changes

1. Drop `--issue NNN` from the dispatch → `Skill("ralph:caretake", args="--mode watch-pr")` (board-wide sweep), and reframe immediacy as "fires the watcher sweep on the event instead of waiting for the heartbeat" (not single-item resolution).
2. Per-file entrypoint prefix: slim rows use `ralph:caretake`, legacy rows use `ralph-hero:caretake`; fix the "identical/no-drift" claims.
3. Enumerate the legacy `SKILL.md` renumber spots (inline `**Priority 2/3**` headers + the "Priority 3" sentinel note) + add a `! grep -q 'Priority 3 .*[Ww]orkflow'` check.
4. Reconcile the dispatch-arg convention break (the `blocked:*` branch emits `--mode <mode>`, not bare `NNN`); update the legacy "bare NNN not --issue" note.
5. Note why `label-routing.md` is NOT touched (classify dispatches the mode directly; it's a separate caretake default-event surface) — or add rows for consistency.
