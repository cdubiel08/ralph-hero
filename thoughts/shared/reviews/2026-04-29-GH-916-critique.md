## Minor observations (non-blocking)

These are observations only — none rise to the level of "needs iteration":

- The Phase 2 test "makes strict forward progress" asserts `chunks[i].charStart > chunks[i-1].charStart` strictly. Given that the existing chunker may produce overlapping chunks (`charStart` of chunk N+1 may equal an earlier value within chunk N's span), this invariant is correct in spirit but check whether the existing greater-than (`>`) holds across all 16 existing tests post-fix; if a test is producing equal `charStart` for adjacent overlapping chunks, the assertion would fire spuriously. The Phase 1 success criteria already cover this via "all 455+ tests still pass," so a test-suite run will surface any conflict.
- The repro command in Phase 1's manual verification block uses `--max-old-space-size=512` — this is more aggressive than the issue's repro (which used `8192`). That's actually a stronger test (proves the fix works at low heap), so this is a positive observation.
- Phase 3 recommends backing up `~/.ralph-hero/knowledge.db` to `.pre-916-bak`. Consider whether the existing reindex codepath drops/recreates tables (which would make the rename redundant) or appends (which would make the rename necessary). Either way, the rename is safe.
