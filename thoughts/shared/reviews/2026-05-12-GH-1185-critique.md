# Plan Critique: GH-1185 — ralph-delegate.sh Foundation + Env-Var Plumbing

## Summary

**Verdict: APPROVED**

The plan is one of the strongest single-issue plans I've reviewed in this repo. It is a single-phase, single-issue S plan with four well-scoped TDD-first tasks, explicit no-regression invariants, a verified-by-grep CI claim, and a properly-bounded scope (adapter extraction is conditional and explicitly deferred to F2). All referenced files and line numbers verified against the working tree.

## Dimension Assessments

### 1. Completeness — PASS

- Single Phase, four tasks (1.1 bats scaffold, 1.2 wrapper impl, 1.3 README, 1.4 hook-bypass smoke test) — each with explicit `files`, `tdd`, `complexity`, `depends_on`, and acceptance checklists.
- All file changes called out with create/modify markers (e.g., `ralph-delegate.bats (create)`, `README.md (modify)`).
- "What We're NOT Doing" lists 8 explicit exclusions, each cross-referenced to the sibling feature that owns it (F2/F4a/F5/F6).
- Phase Success Criteria splits Automated vs Manual verification cleanly.

### 3. Clarity — PASS

- Phase Success Criteria uses the canonical `- [ ] Automated:` / `- [ ] Manual:` split.
- Every task acceptance criterion is a verifiable checkbox.

### 4. Scope — PASS

- "What We're NOT Doing" enumerates 8 explicit out-of-scope items, each linked to its owning sibling feature.
- Adapter extraction (`scripts/lib/openai-compat.sh`) is correctly framed as a **conditional decision point during implementation**, not a forced split. The 80-line threshold gives the implementer a clear trigger.
- No skill integration, no telemetry, no log rotation, no caching — all deferred. Aligned with the parent epic's feature decomposition.
- One ambiguity worth noting (not a blocker): Task 1.4's "hook-bypass smoke test" is scoped honestly as a bats-level stand-in, with the plan explicitly stating "the full end-to-end hook-bypass proof requires F3's reference skill." This is correct boundary-drawing.

## Notable Strengths

1. **Verified CI claim**: The plan explicitly states "Bats is **already integrated** in ralph-hero CI — F1 acceptance should be worded as 'extend the existing bats matrix' rather than greenfield" (lines 43, 60). Confirmed against `ci.yml:124-129`. This avoids the common anti-pattern of "add a CI workflow" when none is needed.
2. **No-regression invariant baked into acceptance**: "with `RALPH_DELEGATE_ENABLED` unset, ralph-hero behavior is bit-identical to today" — both a stated invariant (line 33) and an automated verification item (line 232).
3. **Exit-code semantics distinguish 126 vs 127 deliberately** — the plan motivates this with a one-line rationale ("operator chose not to delegate" vs "operator opted in but endpoint down"), which is the right call for telemetry hygiene.
4. **Honest boundary on Task 1.4**: rather than overclaiming hook-bypass coverage, the plan explicitly says the F1 bats test is a stand-in and the full proof requires F3.
