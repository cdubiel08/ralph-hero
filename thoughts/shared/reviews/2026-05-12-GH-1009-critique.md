## Polish Notes (non-blocking)

These would marginally improve the plan but do not gate approval:

1. **Phase 3 task wiring nuance.** Task 3.2 acceptance criterion 4 says detection layers "AFTER the existing terminal-verdict accept and BEFORE the existing exit 0". Given the current script structure (line 29 `if grep -qE ... then exit 0 fi`), the implementer will need to restructure so the PASS path is not an unconditional `exit 0`. The acceptance criterion implies this but does not spell it out; an impl-agent might patch in place and end up with unreachable code. Consider rewording to "Restructure the existing PASS-accept block so silent-fallback rejection runs before the final exit 0."

2. **Phase 2 freshness-check exact-text contract.** Task 2.1 acceptance specifies the new bash uses `behind=$(git rev-list --count HEAD..origin/main)` but does not specify what to do when `behind > 0`. The Overview prose says "emits a substantive-failure note when N commits behind" — this could be sharpened to specify whether validation continues or stops, and what verdict text is emitted. (The Current State Analysis says the *current* behavior is "continue validation" — the new behavior should be explicit.)

3. **Phase 4 comment phrasing not pinned.** Task 4.1 acceptance criterion 1 lists three bullet points the comment must contain, but does not pin the exact comment header beyond "## Coordinator Note". This is probably fine — small writing latitude is healthy for prose tasks — but if Artifact Comment Protocol consistency is desired, consider `## Implementation Plan — Coordinator Close` or similar.

4. **Test count assertion.** Phase 3 says "PASS count >= 11" (8 original + 1 from Phase 1 + 2 from Phase 3 = 11). This is consistent. Just flagging for the impl-agent to track that the integration check at the bottom says "3 new cases" — matches.

None of these block approval. The plan is dispatch-ready.
