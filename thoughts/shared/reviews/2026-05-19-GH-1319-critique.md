## Additional Observations

1. **Marker format is well-thought-out.** The dual-marker pattern (HTML
   comment for human readability + plain-text breadcrumb for GitHub's search
   API) is correct and matches the upstream `subscribe.py` shape. The plan
   explicitly anchors this in `subscribe.py:217` rather than re-deriving the
   rationale.

2. **`fetch-depth: 0` is the right choice.** The diff resolution needs full
   history so `gh pr diff` (or `git diff base..head`) returns the complete
   changed-files list. The plan calls this out explicitly.

3. **`draft == false` gate** matches the spirit of ralph-pr's Scout Trigger.
   Good defensive choice that avoids spamming scout-auto issues on WIP
   drafts.

4. **`ROUTING_PAT` fallback to `GITHUB_TOKEN`** is consistent with the
   existing PR-triggered workflow pattern.

5. **Risk: cross-phase race condition with Phase 1 (GH-1317).** This plan
   declares `depends_on: [GH-1317]` but if implementation runs in parallel,
   the impl-agent for GH-1319 might race against GH-1317's heuristic
   extraction. This is correctly captured by the explicit `depends_on`; the
   builders team queue should serialize per the group ordering.
