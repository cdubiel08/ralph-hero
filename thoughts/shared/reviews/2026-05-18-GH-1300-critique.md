## Minor Observations (Non-Blocking)

These are advisory only — the plan is approved as-is:

1. **Dry-run gate ergonomics.** Task 1.4 acceptance specifies `issue_number=0` as a "placeholder for dry-run mode where no real issue exists." This is harmless but could be a constant (e.g., `_DRY_RUN_ISSUE_PLACEHOLDER = 0`) in `subscribe.py` for self-documentation. Not required for approval.

2. **Failure mode tracing in `_fire_routine`.** Task 1.3 logs at WARNING on failure but does not return a specific error code or message for the smoke test to verify. The smoke test only checks the success path (`[would-fire-routine]` token). A future iteration could add a `[routine-fire-failed]` marker for negative-path coverage. Not required for approval — the existing failure mode (issue still created, autopilot picks up on next tick) is documented in `## Desired End State`.

3. **README cross-link target.** Task 1.6 acceptance criterion 3 says "Cross-link to `plugin/ralph-hero/skills/director/IOS-REMOTE.md` § 'External producers'" — the implementer should construct this as a relative link from `plugin/ralph-hero/scripts/monitoring-bridge/README.md`, which means the path needs `../../skills/director/IOS-REMOTE.md`. Plan does not specify relative vs absolute. Minor.

4. **Per-day cap reservation.** The plan reserves env var name `RALPH_MONITORING_CRITICAL_CAP_PER_DAY` in README documentation without enforcing it. Suggest noting "follow-up issue: TBD" rather than leaving the reservation in a documentation-only state indefinitely. Not blocking.
