## Key Decisions Verified

1. **Skill-body insertion at SKILL.md (Step 7.0 between 6.6 and 7), not agent-body** — Verified. Plan explicitly says `agents/val-agent.md` is NOT modified (lines 152, 219, 227, 294, 402). Insertion point between live Step 6.6 (line 222) and Step 7 (line 240) is structurally sound. Mirrors F4b's `Step 5.0` H3 placement choice for `skills/ralph-pr/SKILL.md`.

2. **Strict 3-value enum JSON guard (`pass|fail|needs-review`) via `jq -e .classification` + bash case-statement** — Verified at Constraint #8 (line 65), Desired End State #2.b (line 140), Task 1.1 acceptance (line 275). Two-stage validation: `jq -er .classification` extracts the field, then a bash `case` statement restricts to `pass|fail|needs-review`. F4c's deviation from F4a's `jq -e .ranked` (array) and F4b's byte-length+leading-char prose guards is intentional and justified by task type.

3. **Cross-check rule (Constraint #9): automated-check results are ground truth; inconsistencies trigger native fallback** — Verified at Constraint #9 (line 66), Desired End State #2.d (line 141), Task 1.1 acceptance (line 276). Symmetric guards: `delegate=pass + substantive_failures > 0` → fallback; `delegate=fail + failed_checks == 0` → fallback; `delegate=needs-review` → fallback. Justified as F4c-unique because automated checks ARE authoritative ground truth (no analog in F4a/F4b's ranking/summarization tasks).

4. **Threshold gate: `total_checks ≥ 2 AND failed_checks ≥ 1`** — Verified at Constraint #10 (line 67), Desired End State #2.a (line 137), Task 1.1 acceptance (lines 239-247), bats Test 1 (line 368). Hard-coded v1 with telemetry-driven revision pathway noted. All-pass scenario deterministic → no wrapper call, no audit-log line, byte-identical log invariant testable.

5. **FIX classification stays native (delegate enum is `pass|fail|needs-review`, not `pass|fix|fail`)** — Verified at Constraint #13 (line 70), Desired End State #2.f (line 142), Task 1.1 acceptance (line 277), bats Test 3 (line 370). Delegate emits gross pass-vs-fail; mechanical-vs-substantive routing (which selects `VALIDATION FIX` vs `VALIDATION FAIL`) stays in-skill per Step 7's existing logic. Rationale: closed-enum cheap-model task wouldn't handle the mechanical/substantive subtlety reliably.

6. **Mutation preserved: wrapper invocation strictly before Step 8's `create_comment`** — Verified at Constraint #16 (line 73), Task 1.1 acceptance (lines 287-291), Manual Smoke 7 (line 415), Integration Testing (line 434). Automated grep guards: `grep -c 'create_comment' ≥ 1`, `grep -c 'ralph-delegate.sh' == 1`, plus a manual audit that the wrapper invocation appears strictly BEFORE the Step 8 create_comment call.

7. **F4a (GH-1188) and F4b (GH-1189) both merged on main** — Verified by git history: PR #1231 (F4a) merged in commit `28513bac`, PR #1232 (F4b) merged in commit `d63c57ea`.
