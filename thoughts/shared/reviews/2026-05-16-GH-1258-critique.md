# Plan Critique: GH-1258 — cos mode Phase 6 (nightly self-improvement loop)

## Verdict

**APPROVED** — the plan is implementation-ready. It is a single-phase, S-sized
plan with 7 well-bounded tasks, explicit acceptance criteria per task, and a
strong "what we're NOT doing" section. All technical claims about prior cos
artifacts (cos.sh role surface, morning-brief.sh filename convention, launchd
template shape, release.yml path filter) were spot-checked and hold.

must also honor — see Dispatchability note below) is called out explicitly in
the plan's `**Note**` block, so a Builder dispatching tasks in order will not
miss it. Not a blocker.

`gh pr create` but still creating the branch + commit for inspection."

Task 1.7 is conditionally a no-op (only fires if SKILL.md has a phase-status
table). The plan explicitly tells the implementer to `grep` to determine
applicability — appropriate handling for an optional task.

## Risks and mitigations

- **Risk**: `cos.sh --role slow` is invoked 8 times per run (7 grade calls + 1 draft call), each hitting the local mlx-openai-server. If the server is down, all 8 calls fail and the script aborts mid-run. **Mitigation**: the plan already calls this out under "What We're NOT Doing" (no in-script health check) — failure mode is non-destructive (exits non-zero before any git mutations).
- **Risk**: The 95% character-overlap heuristic for "indistinguishable revised prompt" may be too lenient (a prompt with 6% whitespace churn could pass). **Mitigation**: human PR review is the final gate; spurious-revision PRs are an annoyance, not a safety issue.
- **Risk**: First-time install with `RALPH_COS_SELF_IMPROVE=1` set in shell but no `~/.ralph-hero/cos/self-improve/` directory could fail on tmpfile write. **Mitigation**: Task 1.2 acceptance does not explicitly require `mkdir -p ~/.ralph-hero/cos/self-improve/` — recommend (non-blocking) the implementer add this as a defensive first step in the script.

These are advisory; none rise to NEEDS_ITERATION threshold.

## Decision

**APPROVED.** Issue advances to "In Progress" and is ready for `/ralph-impl`.

The two non-blocking recommendations (explicit `RALPH_COS_SELF_IMPROVE_DRY_RUN`
acceptance bullet on Task 1.2; `mkdir -p` defensive step) are worth the
implementer's attention but do not block dispatch — both are caught by Task
1.3's smoke test on the failure path.
