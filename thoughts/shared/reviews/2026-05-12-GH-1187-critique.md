## Verification of the Four User-Flagged Decision Points

1. **`plugin/ralph-hero/CLAUDE.md` routing**: Verified does NOT exist (`test -f` returned false). Only the repo-root `ralph-hero/CLAUDE.md` exists (the project-instructions file). Plan correctly routes the authoring guide to `plugin/ralph-hero/docs/delegation-authoring.md` alongside the existing `docs/cli.md`. Rationale in plan ("creating a plugin-scoped CLAUDE.md would shadow the project-instructions file") is sound.

2. **`plugin/ralph-hero/skills/shared/conventions.md` routing**: Verified does NOT exist (`skills/shared/` contains only `fragments/`, `artifact-comment-protocol.md`, `integration-test-scenarios.md`, `quality-standards.md`). Plan creates topic-specific `delegation-conventions.md` which matches the naming pattern of existing neighbors (`quality-standards.md`, `artifact-comment-protocol.md`, `integration-test-scenarios.md` — all topic-specific). Good call: a generic `conventions.md` would collide with future "X-conventions.md" siblings.

3. **Wrapper-not-adapter enforcement**: Plan calls `ralph-delegate.sh` (the wrapper). Enforcement is in the automated verification: `grep -c 'ralph-delegate.sh' plugin/ralph-hero/skills/delegate-test/SKILL.md` returns `1` AND `grep -c 'openai-compat.sh' plugin/ralph-hero/skills/delegate-test/SKILL.md` returns `0`. These are deterministic, machine-checkable gates. Plan also surfaces this rationale in Shared Constraints (#3) and as the first "Common mistake" in the authoring guide.

4. **No new bats file**: Verified F1's `ralph-delegate.bats` has 8 tests and F2's `openai-compat.bats` has 8 tests — together pinning the wrapper+adapter behavior. The reference skill is a thin operator-invokable proof on top, not new logic. Smoke 1-4 are sufficient: each tests a distinct exit-code branch (0/127/126) plus teardown. The "Worked-example fidelity" visual-diff check is the strongest guard — if the skill drifts structurally from the authoring guide, that's caught by review.
