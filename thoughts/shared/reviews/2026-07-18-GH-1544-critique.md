# Review: Decision-gated plan approval + autonomous merge default (gate flip)

## Plan Reference

[thoughts/shared/plans/2026-07-17-GH-1544-decision-gated-plan-approval-merge-auto.md](../plans/2026-07-17-GH-1544-decision-gated-plan-approval-merge-auto.md)

## Strengths

- **Every load-bearing claim was verified against source and holds.** `hero/SKILL.md:2` really does say "human plan-approval gate by default" while line 105 resolves `${RALPH_REVIEW_MODE:-interactive}` and line 104 resolves `${RALPH_REVIEW_PLAN:-auto}` — the contradiction is real. `review-plan-gate.sh:40-44` detects exactly the header-string / Approve+Request-changes label pair the plan describes, so the `Decision:`-header naming contract genuinely needs no hook change. `doc-structure-validator.sh:56` has the fence-strip `awk` the plan proposes to reuse. `loop-wrapper.md:38` confirms `plan:review` terminates on `Queue empty.`, so registering `PLAN AWAITING DECISION` as a progress sentinel is the right (and necessary) plumbing.
- **The plan models its own contract.** It carries a populated `## Design Decisions & Open Ambiguities` section with three resolved decisions (park location, skip scope, `RALPH_REVIEW_PLAN` semantics) plus the sentinel — the Phase 1 manual criterion "this plan doc itself passes the updated validator" is a nice self-referential check.
- **The partial-autonomy trap was caught at design time.** Rejecting the naive `RALPH_REVIEW_PLAN=interactive` flip (AskUserQuestion inside a `--mode auto` tick blocks the loop forever) and making the human pause content-driven rather than positional is the correct resolution of the `auto-mode-is-end-to-end` tension the plan itself cites.
- **Merge-safety invariants are explicitly preserved and independently true.** `merge-review-decision-gate.sh` is a PreToolUse:Bash hook that fires regardless of `RALPH_REVIEW_MODE`, and `CHANGES_REQUESTED` has no carve-out — so the flip changes who initiates review, not what can merge. Rollback is two independent levers (env export vs PR revert), correctly distinguished in Migration Notes.

## Gaps

- **[File ownership — Phase 2]** The auto flow fires `PushNotification(title="Decision needed #NNN", ...)` from the plan-review workflow body, but `ralph/skills/plan/SKILL.md` `allowed-tools` (lines 77-101) does **not** include `PushNotification` (hero and caretake carry it; plan does not). Skill `allowed-tools` is pre-approval — a missing entry means a permission prompt mid-flow, which in an unattended `plan:review` drain stalls or gets denied. Phase 2's Changes Required must add `PushNotification` to the plan skill frontmatter, and should state the failure semantics (mirror `caretake/modes/unblock.md:231`: notification failure does NOT fail the flow — the comment is the source of truth). Fix location: Phase 2 § Changes Required, new file entry for `ralph/skills/plan/SKILL.md`.
- **[Risk coverage — Phase 2 #3]** The idempotency check is ordered **after** the review-agent verdict ("After the review-agent verdict: idempotency check first"). The plan's own Key Discovery notes the autopilot classify tick re-dispatches `/ralph:plan --mode review` for every Plan in Review issue on every pass — so a plan held awaiting a human decision gets a **fresh fable/opus critique dispatch on every tick**, each producing an identical predetermined outcome. Comment/notification duplication is handled; repeated top-tier critique cost is not. Fix: hoist the `## Decision Request` comment scan to before the review-agent dispatch — if a request exists with no later human comment, emit `PLAN AWAITING DECISION` and stop without dispatching the critique at all. Fix location: Phase 2 § Changes Required #3, reorder the branch logic.

## Failures

None.

## Recommended Changes

1. **Phase 2**: Add `ralph/skills/plan/SKILL.md` to Changes Required — append `PushNotification` to `allowed-tools`, and document fail-open semantics for the notification (comment is source of truth, notification failure never fails the review).
2. **Phase 2 #3**: Reorder the auto branch — run the `gh` comment scan for an existing `## Decision Request` *before* dispatching the review-agent critique; short-circuit to `PLAN AWAITING DECISION` when the request is unanswered. Only dispatch the critique for first-review or answered-decision passes.
3. **Phase 3 automated verification (nit)**: `grep -c "human plan-approval gate by default" ralph/skills/hero/SKILL.md` exits 1 when the count is 0, so as written it fails under `set -e`/CI semantics. Use `! grep -q "human plan-approval gate by default" ralph/skills/hero/SKILL.md` instead.
4. **Phase 2 #2 (nit)**: Note the AskUserQuestion per-question option ceiling — a `#### Decision:` block with more than ~4 options needs the overflow rule stated (truncate to top options + "Other" free-text escape hatch already specified).
