# Review: Add CI Doc-Consistency Check for Agent/Skill/Tool Rosters (GH-1458)

## Plan Reference

[thoughts/shared/plans/2026-05-28-GH-1458-ci-doc-consistency-check.md](../plans/2026-05-28-GH-1458-ci-doc-consistency-check.md) (iterated at commit `4f713f1f`)

## Strengths

- The central design decision — **bidirectional** check for the exhaustively-documented agents/skills, **one-directional** (documented⊆source) for the curated tool roster — is correct; a bidirectional tool check would false-fail constantly.
- Agent (16) and skill (9, excl `shared`/`using-html`) rosters verified to match source on `main`; the corrected tool extraction yields 38 source names and 0 documented-but-missing.
- Repo-idiomatic: bash script modeled on `verify-mcp-pins`, independent peer CI job, self-validating (runs on its own PR).

## Gaps

- Minor: research called it "effectively S" while the plan keeps M. M is retained and defensible — the extraction is fiddlier than a trivial grep (as the first-pass bugs showed). Non-blocking.

## Failures

None (post-iteration). The **first-pass review** (NEEDS_ITERATION) found 3 real tool-extraction defects:
1. anchored regex `server\.tool\(\s*"(ralph_hero__…)"` matched 0 (names are on the next line);
2. scope `src/tools/*.ts` missed `ralph_hero__health_check` (in `src/index.ts`) → would fail on main;
3. count double-counted ("38+2=40" vs 38 total).
All three were fixed in commit `4f713f1f` (plan + research) and **empirically re-verified**: literal `"ralph_hero__[a-z_]+"` over `mcp-server/src/**/*.ts` (excl `__tests__`) = 38 names incl `health_check`; 28 documented names, 0 missing.

## Recommended Changes

Already applied (literal-pattern extraction, full `src/**` scope, corrected count). None outstanding. The implementer MUST use the corrected extraction (not the original anchored regex).
