research doc, decouples the independently-safe ralph-pr conversion, supersedes

## Strengths

1. **Research-grounded path selection.** The research doc enumerates Paths A/B/C
   with trade-offs; this plan picks B with explicit reasoning ("Path B achieves
   architectural cleanup without the conversion"). The "context crash claim
   unverified" finding is correctly used to justify NOT converting merge.

2. **Decoupling the ralph-pr half.** Splitting the original haiku-dispatch plan
   into two independent halves (merge=rejected, pr=safe) is the right call.
   ralph-pr has zero nested `Skill()` calls, so its conversion is mechanically
   safe and reduces blast radius.

3. **Standalone-safety guard.** The Task 1.2 acceptance criterion that
   `just merge NNN` on an unreviewed PR must output `MERGE BLOCKED — review
   required` is exactly the right preservation. Without this, removing the gate
   from ralph-merge would create a footgun where standalone callers silently
   skip code review.

4. **Backward-compatibility audit in Shared Constraints.** Lines 39-42 enumerate
   five distinct compatibility surfaces (RALPH_REVIEW_MODE, CODE_REVIEW_FEEDBACK
   contract, MERGED/MERGE BLOCKED/MERGE NOT READY contract, hooks, ralph-pr
   safety). This is unusually thorough.

5. **Tightly-coupled task ordering.** Task 1.2 depends on 1.1 because of the
   "neither owns the gate" window. Task 1.5 depends on 1.1+1.2+1.3 because
   verification needs the modifications in place. The dependency graph is
   correct.
