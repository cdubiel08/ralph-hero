## Minor non-blocking issue

**Line 211 constraint pointer is mislabeled.** Phase 3 Task 3.1 acceptance line 211 says:

> Body cites the parent plan's Shared Constraint 13 verbatim as the authority for the allowlist

But the parent plan-of-plans (`2026-05-16-GH-1267-unified-agent-system-epic.md`) has Shared Constraints numbered 1-10 only. The constraint being pointed to (the sre-fixit allowlist policy) lives in **this child plan's "Feature-specific constraints" section** at line 59 (constraint 13 of the child plan).

Suggested wording: `Body cites this plan's Feature-specific Constraint 13 verbatim as the authority for the allowlist`.

This is not blocking because:
1. The allowlist text the implementer needs (replica/drain/restart/delete-pod with no --force, no --cascade=foreground) is fully specified at line 59 of this same plan
2. The implementer can read the surrounding context and find the right constraint
3. Phase 4's similar citation (line 257, "Shared Constraints 6 and 7") IS correct — those constraints exist in the parent plan, so the language pattern is just inconsistent across two lines of one plan

The implementer can fix this inline during implementation without a re-plan, or leave it as-is — either is fine.
