## Risk Notes (Non-Blocking)

These are observations the plan already handles but worth surfacing for the implementer:

1. **Parent epic plan missing.** Constraint 7 + Task 1.7 already prescribe stub creation. Implementer should follow the stub schema exactly (frontmatter fields enumerated in Task 1.7 acceptance) so future readers of the GH-1314 epic find a coherent document rather than just the evidence section.

2. **Director dispatch path is non-deterministic.** Task 1.5 offers passive (autopilot tick) vs active (manual `/ralph-hero:director --issue NNN`) paths. For reproducible evidence, the active path is strictly preferable — the plan correctly records "Director dispatch path" as a recorded field so future readers know which branch fired.

3. **Conditional scouts dispatches may not fire.** The plan acknowledges that only `a11y-scan` is always-fire; `test-e2e`/`storybook-test`/`visual-diff` depend on detected artifacts. Task 1.5 records "Conditional skills fired" as a field, so a minimal a11y-scan-only run still produces valid evidence.

4. **Cleanup is the last task.** If validation surfaces unexpected behavior, the implementer should NOT close the fixture PR/issue until evidence is fully captured. Task 1.8 depends on 1.7 (evidence written), which is the correct ordering.

5. **`/components/` path under `plugin/ralph-hero/`.** A reviewer unfamiliar with the fixture may flag the directory as new. The PR body (Task 1.2 acceptance) should explicitly call out non-merging intent in the title and body to prevent accidental approval-and-merge by another reviewer.
