# Plan Review: GH-0920 - knowledge_search Retrieval Eval as CI Regression Guard

## Summary

Plan is high quality and ready for implementation. All five quality dimensions
pass. The plan is unusually well-grounded: it cites the heap-bench precedent
(GH-913) for the CI pattern, references the verified post-reranker baseline
(Hit@5 = 87.5%) for the threshold floor, and pre-bakes seven shared constraints
that pre-empt the most likely implementation pitfalls (libc++ abort on hard

etc.).

## Scope — PASS

"What We're NOT Doing" section enumerates seven specific exclusions, each
mapped to a research finding or issue non-goal:

- No 30+ query expansion (issue's explicit non-goal).
- No alternative-retriever comparison (one-shot bench, not a guard).
- No automated golden-query generation.
- No reranker in the CI path (cold-start cost — Shared Constraint #2).
- No PR comment posting (deferred per research finding #5).
- No path filter (research recommends running on every PR until CI cost is shown).
- No `/ralph-split` decomposition (single S issue; phases ride in one PR).

The constraint that "edits to live `thoughts/shared/` documents must NOT
affect the eval" (Shared Constraint #4) is a strong scope boundary that
prevents corpus drift.

## Minor Notes (non-blocking)

- Task 2.4 imports `db.ts` and `search.ts` as both `.ts` and `.js` exist for
  some files in this codebase. The plan correctly uses `.js` suffixes per the
  NodeNext ESM convention; verified via `grep` against neighboring code.
- Task 3.2's HuggingFace cache key uses `package-lock.json` hash, which will
  bust the cache on any unrelated lockfile change. Acceptable trade-off for a
  ~90 MB model — the alternative (hashing only embedder version) would
  require a custom step. Not worth changing now.
- Phase 4's task 4.2 verification asserts `hitAt5 === "7/8"`. If a future
  reranker tweak nudges the score, this hardcoded check would need updating.
  Acceptable for a one-time migration verification; would be a problem only
  if eval-rerank.mjs evolves into a CI gate (which the plan explicitly
  defers).
