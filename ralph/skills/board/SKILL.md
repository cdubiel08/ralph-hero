# /ralph:board — orientation, intake, answers, health

The CLI is `${CLAUDE_PLUGIN_ROOT}/scripts/board` — that placeholder resolves to wherever this plugin is installed, so it works from any repo; never substitute a repo-relative path. Below, `board` is shorthand for it. The Projects V2 UI is the dashboard. This skill is a thin human front-end — judgment stays with the user.

- **status / empty args** — `board list`, then a 3-5 sentence read: what's in flight (claims + age), what's blocked on a human, what's next. No dashboards; the board UI renders itself.
- **next** — `board next`, one-line recommendation, offer to dispatch `Skill("ralph:work", args="NNN")`.
- **answer** — for each Human Needed item (`board list --state human`): show its Decision-needed comment, collect the user's answer (AskUserQuestion, one per item, recommendation first), post it as a comment, then `board move NNN <backlog|in-progress>` per the answer. An item `reconcile` reopened as an unevidenced **apply unit** asks a narrower question — *was the change actually deployed?* Its resolution is evidence or a cancel; a re-close without evidence is refused and the item comes straight back.
- **new "<title>"** — crystallize the user's description into `board create <lane> --title … --body …` (body: outcome + acceptance in the user's words, no template ceremony). **The lane is not optional and has no default** — filing an issue is not approving it for autonomous pickup: `--backlog` is approved-and-ready and REQUIRES `--priority P0..P3` and `--estimate XS..XL`; `--intake` is tracked-but-not-yet-approved, needs neither, and is invisible to `board next`/`frontier` until a human runs `board move NNN backlog`. When the user has not decided, `--intake` is the honest lane — it keeps the item visible in `board list` and in `board tend-queue` instead of parking it in someone's head. Offer `--parent`/`board dep` wiring when it obviously belongs to existing work.
- **approve / what's waiting** — `board list --state intake` is the pending-approval queue; doctor's advisory `intake-stale` line names items that have waited past `RALPH_SMELL_INTAKE_DAYS` (14). Approval is `board move NNN backlog`, which refuses without a Priority and an Estimate — Backlog means rankable, not merely accepted. Rejection is `board cancel NNN -m "<why>"`. There is no edge back to Intake: work that collapses under review is Canceled plus a fresh Intake item.
- **proposals** — `/ralph:tend` files closure proposals as `<!-- ralph-tend:v1 proposed -->` marker comments (on Backlog items, and on closed ones it judges unevidenced); they re-surface as the `proposed` category of `board tend-queue` and as doctor's `tend-proposal-stale` line **until they are answered**. Disposing of one is a human call, and every disposition is recorded: `board cancel NNN -m` (superseded) and `board move NNN done --why "<how it was delivered>"` (already delivered — the Done evidence gate still applies) answer it by closing; `board reopen NNN` (unevidenced close) writes the resolution itself. To **reject** one — leave the item open, the proposal was wrong — run `board resolve NNN --reject -m "<why not>"`, which writes the durable `<!-- ralph-tend:v1 resolved -->` marker. Rejecting by doing nothing does not work and never did: nothing observable changes, so the next pass reads an unanswered proposal.
- **doctor** — `board doctor`, relay findings plainly; offer `--fix` for stale claims and anomalies (it posts comments for every correction). Three checks report on **apply units** (work whose completion is a deploy, not a merge) and read `ok — apply kind not enabled` in repos that never opted in: `merged-unapplied` (the code landed, the deploy didn't — usually the real next action), `apply-verify-elapsed` (a proof point that was scheduled for the future has come due), and `apply-closed-unevidenced` (a completion claim with nothing behind it — the only one that fails `--strict`; `--fix` reopens those to Human Needed). The `installed-plugin` info line (GH-1825) is the one whose remedy is the *human's machine*, not the board: it compares the plugin copy agents actually call (the `installPath` in `installed_plugins.json`) against the release each gate this repo relies on shipped in, so "below 0.1.81, the apply close gate is not enforcing" is something to fix by updating the plugin — doctor cannot, and never treats it as a finding.
- **readiness** — `board readiness`, relay as recommendations, never demands: what the repo already supports, then the one or two gaps that matter for the autonomy the user actually wants (Level 1 interactive / 2 unattended / 3 loop). Offer to file chosen recommendations as board items (`board create --backlog …`, or `--intake` when the user has not committed to them) or to help adopt one now; never auto-remediate, and never treat a gap as a blocker — a repo's own CI/CD ladder is its own business.

Anything this skill leaves on an issue that asks for a decision — an escalation comment, an open question captured at intake, an item parked in Human Needed — is written **phone-answerable** per [../work/references/escalation.md](../work/references/escalation.md), which states the bar and — the part no contract can check — how to compose the option set. It applies equally to a decision you relay to the user *in this session*: the first line is all a notification carries either way, and this is the skill that most often has one to relay.

Never mutate state beyond what the user asked for in this sitting; anything execution-shaped goes to `/ralph:work`.
